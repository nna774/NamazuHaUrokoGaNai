# ノイズ特性と検出限界（実測まとめ）

本機のノイズの正体と検出限界の記録。

**「要点」以降の確定値は device 0001（新潟県湯沢町・IIS3DHHC）のもの**で、2026-07 に
実イベント（福島県沖 20:53 / 令和8年熊本地震 16:27）周辺の静穏区間から切り分けた。
据え付けを変えた後の暫定測定は末尾の[測定ログ](#測定ログ暫定)に分けてある。**確定値の表は
本据え付け後の再測定を通すまで書き換えない。**

## 要点

- **ノイズフロアはほぼ白色 ~25-30 µg/√Hz**（全帯域で平坦）。broadband RMS ≈ **0.18 gal**（0-50Hz積分）。
- これは**センサ/電子系の熱雑音**であって環境振動（足音・生活振動）ではない。
  根拠: 静穏時PSDが平坦（白色）＝環境振動なら低周波へ急峻に立ち上がるはず。揺れの時間帯に
  人は動いていなかった観察とも整合。
- 例外は **z軸（垂直）のみ低周波 <0.2Hz で 90-130 µg/√Hz に突出**。重力を担う軸で
  傾斜・熱ドリフト・1/f 雑音が乗る。→ 遠地弱震では z を捨てて水平2軸が有利。

### 実測ASD（静穏時・z軸）

| 帯域 | ASD [µg/√Hz] |
|------|--------------|
| 0.5–1.5 Hz | 38 |
| 1–3 Hz | 33 |
| 5–10 Hz | 29 |
| 20–40 Hz | 28 |
| <0.2 Hz(z) | 90–130（垂直のみ突出） |

- データシート: IIS3DHHC = 45 µg/√Hz（±2.5g/16bit）。ファームは 1kHz 読み→10平均で 100Hz 化
  （`firmware/src/config.h` `kOversample=10`。帯域外を √10 で削減）→ 実効 in-band ~25-30 と整合。
- 量子化ノイズ（0.076 mg/LSB）は ~3 µg/√Hz で律速ではない。

## 連続震度での見え方（窓長の影響）

- 計測震度の移動窓は実機・tools とも **60秒**（気象庁準拠。`firmware/lib/Shindo/Shindo.h`
  `kWindowSamples`、`tools/jismo/realtime.py` `WINDOW_SECONDS`）。
- 60秒窓のベースライン ≈ 震度 **-0.55**。**5秒窓**にすると中央値 ≈ **-0.80**（過渡の居座りが
  消えて谷が深くなる）が、標準偏差は 0.100→0.128 と増える＝**フロア自体は下がらない**。
- 5秒窓は「静穏/イベントのコントラスト」向上には効くが、計測震度の定義から外れる。
  **検出用途には短窓連続震度より STA/LTA が筋がよい**（居座りもフロア悪化もなく短時間過渡を出す）。

## 他機との比較（同一地震・ほぼ同距離）

令和8年熊本地震（震央距離 東京・湯沢とも約 880km）:

| | 東京 ADXL355 | 湯沢 IIS3DHHC（本機） |
|---|---|---|
| 震度ベースライン | ≈ -1.2（≈0.085 gal） | ≈ -0.55（≈0.18 gal） |
| ノイズ密度(データシート) | ~25 µg/√Hz | 45 µg/√Hz |
| 熊本地震のバンプ | 震度0 まで +1.2階級（明瞭） | 連続震度では埋没 |

- フロア差（約2倍）は主に**センサのノイズ密度差**（25 vs 45 ≈ 1.8倍）で説明でき、距離でも設置でもない
  （両者ほぼ同距離）。ADXL355 は低周波(1/f)特性も良く、遠地=低周波に二重に有利。

## 検出できた／できなかった

- **20:53 福島県沖 M4.0 深さ50km（震央268km）**: 3軸・低帯域(0.3–1.5Hz)STA/LTA で
  P波到達 20:53:42 に最有力候補。ただし背景から明確には抜けず **probable**。
- **16:27 令和8年熊本地震（震源距離 ~870km）**: 3軸・連続震度では**完全埋没**。
  **z軸を捨てた水平2軸 STA/LTA（0.5–2Hz）で P波到達 16:29:27 に STA/LTA=3.6、
  記録中最大クラスタ＋直線性0.89** → **probable detection**（→ event `0001-59507458` に保存）。

## 実務結論

- **現設置はセンサ律速**。遠地弱震を狙うなら順序は **①センサ更新（ADXL355級/速度計）→ ②設置改善
  （動線・空調から離す・基礎への剛結合・断熱）**。設置改善は現機材では二次的（フロアが白色＝センサ）。
- **現機材の繋ぎ**: 水平2軸（`detectlab.py --axes xy`）＋低帯域 STA/LTA。z軸の低周波ノイズを避けられ、
  遠地巨大地震の実体波(P)くらいは掠める。
- **長周期（遠地の表面波, <0.2Hz）は加速度計では原理的に不利**（a ∝ f²·D）。狙うなら速度計/広帯域
  地震計＋静穏・断熱設置が要る（詳細は会話ログ参照）。

## 再現

```bash
# ノイズASD（静穏区間のPSD）: welch で振幅スペクトル密度を出す（scratch スクリプト相当）
# 連続震度の窓比較: jismo.realtime.RealtimeIntensity(window_seconds=5 vs 60)
# 水平2軸検出: 
python tools/detectlab.py --csv <win>.csv --axes xy --band 0.5 2 --sta 2 --lta 60 --thr 2.8 \
    --eew "32.803,130.708,10,2026-07-28 16:27:18"
```

計測震度 ↔ 加速度: `I = 2·log10(a0) + 0.94`（a0 は 0.3秒累積超過の代表振幅）。

### 2026-08-02 ADXL355 初回・据え付け前

- 機材: `EVAL-ADXL355-PMDZ`（±2.048g / 20bit / 0.00390625 mg/LSB）、ESP32、`-e adxl355-sensortest`
- 据え付け: **未固定**。基板をブレッドボード脇に置いただけ、机上。電源投入から約8分後に測定開始
- キャプチャ: 300秒（`capture_serial.py --sensor adxl355`）→ `adxl_rest.csv`

| | x | y | z |
|---|---|---|---|
| in-band ASD (0.5–40Hz, DC除去後) | **20.3 µg/√Hz** | **19.8** | **37.2** |
| broadband RMS (0–50Hz) | 2.478 gal | 0.376 | 0.651 |
| 直流（重力＋オフセット） | 216.7 gal | -34.8 | 964.8 |
| ドリフト（先頭10s→末尾10s） | **8.27 gal** | 1.24 | -1.96 |

- パワーの **98.2% が 0–1Hz**（`spectrum.py`）。x軸の broadband RMS が大きいのは
  ほぼ全部このドリフトで、in-band のノイズではない。通電8分では熱が落ち着いていない。
- 3軸合成は 0.9935g（重力）で、20bit デコードとスケールの正しさはここで確認できている。
  ただし重力がほぼ -X に乗っており、**基板は寝ておらず立っていた**（軸は N/E/Z に未整列）。
- 記録全体（300秒）の FFT版 計測震度 **-0.77**（`a0=0.139gal` / `peak=0.276gal`）。
  ただしこれは §連続震度での見え方 にある**60秒窓のベースライン -0.55 とは別の量**なので
  直接は比べられない。
- この測定中に震度算出側の不具合（ドリフトで窓の端が暴れる）が発覚している。上の値は
  **修正後**のもの。経緯は [intensity_pitfalls.md](intensity_pitfalls.md)。

参考として、同じ手順・同じスクリプトで `tools/rest.csv`（IIS3DHHC・60秒・机上）を測ると
in-band ASD は x 59.5 / y 72.4 / z 77.6 µg/√Hz だった。**水平でおよそ3倍の差**がある。

ただし比較には次の留保が付く。

- 上の「実測ASD」の表（25–30 µg/√Hz）とは**算出手順が違う**（あちらは実イベント周辺の
  静穏区間、こちらは Hanning 窓の単発FFT）。**同じ手順で測り直した値どうしでしか比べるな**。
- 両者は据え付けも時刻も場所も違う。**順位が付いた**以上のことは言えない。
- z が水平の約2倍という傾向はセンサを換えても残った。[adxl355.md](adxl355.md) §6 の判定
  ルールでは「架台の熱ドリフト/傾斜が主因」に傾く材料だが、仮据え付けでは断定しない。
