# 固定後の背景ノイズ震度を実測し、notify閾値(k,l)を下げる余地を確認した

## 何を決めたか

`notify_prompt_min`(k、既定3.0)・`notify_confirm_min`(l、既定1.5)を実際にいくつまで
下げてよいかの判断材料として、コンクリブロック固定後の背景ノイズが到達する計測震度を
実データで測った。**値の変更自体はまだ適用していない**（本ログは調査と提案の記録）。

- `.s3cache/`(2026-08-11ログで作った、S3生波形のobject keyミラーキャッシュ)に
  たまたま残っていた2026-08-17 23:00〜08-19 11:00(UTC、約36時間、device1/2とも
  固定済み後)を使い、5分刻みで120秒窓(確定報相当)・60秒窓(速報相当)のFFT計測震度を
  算出した。`HOLD_SECONDS`等の継続時間フィルタは掛けず、「その窓を評価したら何震度と
  出るか」の天井だけを見ている。
- 結果、device1は confirm相当 90%タイル=-0.5・max=-0.4、device2は 90%=-0.8・max=-0.6。
  **36時間、震度階級「0」(0.5未満)にすら一度も届いていない**。
- 併せてJMAフィルタ後合成加速度そのものを対数軸でプロットして目視確認した
  （最初、重力込みのraw `|a|`≈980〜1000galでプロットしてしまい何も見えなかった。
  フィルタ後の実際の「揺れ」成分で見て初めて意味のあるグラフになった）。
  こちらも震度0.5のライン(0.603gal)に一度も触れていない。

  ![device1/2のJMAフィルタ後合成加速度(対数軸、震度0.5/1.0/1.5/3.0のラインを重ねた)。
  36時間通してI=0.5のラインにすら触れていない](img/2026-08-22-notify-threshold-noise-waveform.png)

- 最初にプロットして「役に立たない」と捨てたraw `|a|`(重力込み、フィルタ前)も、
  別の観点で見ると面白い副産物だった。**device1は36時間の中で≈984〜986galの間を
  ゆっくり(数時間スケールで)ドリフトしている**(hour20〜25あたりで山になる緩やかな
  変動)のに対し、**device2は≈992〜993galでほぼ完全にフラット**。両機とも同じ
  コンクリブロック固定なので、これは設置方式ではなくセンサ自体(device1=IIS3DHHC、
  device2=ADXL355)の低周波特性の差と見てよい。2026-08-11ログのz軸<0.2Hz ASD比較
  (device1: 81.8→80.8µg/√Hzでほぼ無風、device2: 92.9→27.9µg/√Hzで7割減)とも整合する
  ——device2の方が低周波(熱ドリフト・傾き)に強いセンサ、という既存の理解を
  別の見え方(生の重力magnitudeの時間変化)で裏付けた形。

  ![device1/2の生|a|(重力込み、フィルタ前)envelope。device1は数時間スケールで
  ±1gal程度ドリフトするが、device2はほぼフラット](img/2026-08-22-notify-threshold-raw-magnitude.png)

## なぜ

ユーザーから「コンクリブロックに固定してからはそんなに揺れることないから、もっと
低いところから通知してもいいかな」と相談された。ちょうど直前に見ていた
八丈島東方沖M5.5イベント(`0002-59577127`、震度0.9・device_promptのみ)が
現行閾値(k=3.0, l=1.5)には遥かに届かず通知されなかった例だったので、
「そもそも背景ノイズはどこまで低いのか」を実測してから閾値を決めるべきと判断した。

## 何が覆ったか

特に無し。初めての定量評価。強いて言えば、raw `|a|`(重力込み)でプロットしても
ノイズは見えない、フィルタ後合成加速度で見る必要があるという点で試行錯誤した。

## 次に何が可能になったか

- 実測ノイズ上限(震度-0.4〜-0.8)に対し、`notify_confirm_min=0.7`・`notify_prompt_min=1.5`
  あたりまで下げてもノイズ比3倍程度のマージンが残る、とユーザーに提案した。
  最終値はユーザー判断待ち。決めたら `terraform/terraform.tfvars` を直して
  `terraform apply` するだけで反映できる（コード変更は不要）。
- **通知閾値を下げても、`cloud_confirmed`自体が立たないケースは変わらず速報のみになる**
  ことは明記した。八丈島沖の例(震度0.9)は継続時間が`HOLD_SECONDS`に届かず未確定
  だったので、`notify_confirm_min`をどれだけ下げても確定報としては通知されない。
  この種のケースを拾いたいなら`HOLD_SECONDS`側の話になる。
- 解析スクリプトはメインチェックアウト側の`tools/_scratch_notify_threshold.py`
  （震度分布の集計）・`tools/_scratch_plot_noise_waveform.py`（フィルタ後波形PNG化）・
  `tools/_scratch_plot_raw_magnitude.py`（フィルタ前生magnitude PNG化、長期ドリフト用）
  としてスクラッチのまま残した（`tools/README.md`の「何度も条件を変えて解析する」運用に
  沿う再利用資産。コミット対象外）。次にノイズフロアやドリフトを見たくなったら使い回せる。
- device1の低周波ドリフトが今後もこの規模で続くようなら、`docs/noise.md`の
  センサ選定比較（device1=IIS3DHHC vs device2=ADXL355）に正式なデータ点として
  追記する価値がある(今回はnotify閾値調査の副産物として見つかった段階、本格的な
  追記はまだ)。
