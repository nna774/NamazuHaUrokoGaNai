# 2026-08-28 窓別SNR/直線性の判定を画像にも文字で入れる

コーダ想定域窓を追加した後、「結果を画像に文字として入れられないか」という提案があり、
福島県沖M4.5のデータで2パターンをプロトタイプ化して比較した:

- **パターンA**: P窓・S窓・コーダ想定域の各帯の近くに両機の数値を注記
- **パターンB**: 図の隅にまとめて小さい表を1個貼る

パターンAはP窓・S窓が時間的に近く、注記ボックスが重なって文字が潰れた（3窓に増えた今、
帯ごと注記は構造的に破綻しやすい）。パターンBは窓が増えても表の行が増えるだけで済み、
明確に見やすかったため採用した。

## 実装

`tools/detectlab.py`:
- `classify_snr_wrect(snr, wrect) -> str`を切り出し、`report()`のテキスト出力と
  重ね描き表で判定ロジックを共有する。
- `report()`を、窓別の`(label, snr, wrect, verdict)`のリストを返すように変更
  （`--eew`未指定時は`None`）。
- `overlay_source()`内で`report()`の返り値を、main()スコープの`window_reports: dict[int, list]`
  （dev→結果）に集約する。`per_device`タプルの形（6要素）は変えていない——
  `pair_rolling_correlation()`が固定形で分解しているため、別引数として通す方が安全。
- `plot_overlay()`に`window_reports`引数を追加。2機重ね描き時、右上に窓×機体の
  SNR/直線性/判定の表を`axs[0].table()`（実グリッド）で貼る。**凡例(device 1/2)は
  表と衝突するため左上へ移動**（`--eew`なし・表を出さない時は従来通り右上のまま）。

### レイアウトの試行錯誤（ユーザーレビューで2回直した）

1. 初版は文字列をパディングして手組みした表を`fig.text()`で図全体の座標(0.99, 0.99)に
   置いたが、和文フォントはプロポーショナルなのでパディングでは列が揃わず、かつ
   suptitleと同じ高さに置いたためタイトル文字列の末尾と衝突した。
   → `axs[0].table()`の実グリッドに置き換え、`axs[0]`の内側（axes座標 y=0.60〜0.98）に
   移動して解決したが、STA/LTAの波形と重なる位置になった。
2. ユーザー指摘で「波形と被らない・タイトル横の元の位置に戻したい」と分かり、
   `axs[0]`の**上端(y=1.0)より上**（axes座標 y=1.20〜1.48）に配置し直した。
   セルの内側パディング(`Cell.PAD`)も0.1→0.03に詰めてタイトルの右側に収まる幅にした。
3. それでもまだ問題が残っていた——`secondary_xaxis("top")`で出している実時刻の目盛
   （22:41:40等）がちょうどその高さ(axes座標 y≈1.0〜1.15程度)にあり、表の右側の下に
   隠れてしまっていた。表の`y0`を1.02→1.20へさらに上げ、目盛の帯より上に出すことで解決。

最終的な配置は「STA/LTAパネルの真上・実時刻目盛のさらに上・タイトルの右側」という
狭い帯（`bbox=[0.56, 1.20, 0.44, 0.28]`、axes座標）。

## 動作確認

福島県沖M4.5・浦河沖M6.0の2件を`--out`付きで再実行し、表・凡例・実時刻目盛・波形の
どれとも衝突せず全部読めることを確認（レイアウトはユーザーに画像で都度確認してもらい、
上記3段階の手直しを経て確定）。`--eew`なしのケースも表が出ず凡例が右上のままであることを
確認（既存挙動の回帰なし）。テスト1件追加（`classify_snr_wrect`の閾値）、
`pytest tools/tests`は82件通過。
