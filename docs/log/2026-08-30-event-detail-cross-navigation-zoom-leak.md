# イベント詳細ページで別イベントへ移ると時間ズーム(t)が誤って引き継がれる不具合を修正

## 症状

イベント一覧である機のイベント（例: `0001-59600556`）を開き、グラフをドラッグ拡大して
`t=<fromUs>-<toUs>` 付きのURLになった状態（例: `#event/0001-59600556?...&t=1788016687730767-1788016713596184`）
から一覧に戻り、別のイベント（例: `0002-59595349`）をクリックすると、遷移先のURLにも
同じ`t`が付いたままになる（`#event/0002-59595349?...&t=1788016687730767-1788016713596184`）。
遷移先イベントの実時刻と`t`の範囲が対応していないため、グラフ表示が壊れる。

## 原因

`dashboard/app.js`の`eventHash(id)`は、モジュール変数`eventZoom`（今表示中のイベントの
ズーム状態）を無条件に`t`パラメータへ埋め込んでいた。この関数は2種類の呼び出し元で
使われている。

- 自己参照（`currentEventId`を渡す）: 縦軸レンジ変更・軸on/off・ドラッグズーム自体。
  現在のズーム状態をURLへ反映したいので`eventZoom`を含めるのが正しい。
- 別イベントへの遷移: 一覧の行クリック(`tr.onclick`)・関連イベントリンク
  (`renderEventInfo`内`related_events`)。遷移先は別イベントなので`eventZoom`
  （前のイベントの時刻窓）を引き継ぐ意味がない。

後者の呼び出しでも`eventZoom`がそのまま使われていたため、ズームしたまま一覧に戻って
別イベントをクリックすると症状のURLが生成されていた。

## 修正

`eventHash(id, includeZoom = true)`に引数を追加し、別イベントへの遷移側
（一覧行クリック・関連イベントリンクの2箇所）だけ`includeZoom=false`で呼ぶようにした。
自己参照の3箇所（`event-yrange`変更・軸on/off・`applyEventZoom`）は引数省略のままで
挙動を変えていない。

`route()`側は元々`params.t`が無ければ`eventZoom = null`にリセットする作りだった
（コメント「別イベントへ移った時のリセットも兼ねる」）ため、遷移リンクから`t`を
削るだけで直る設計になっていた。
