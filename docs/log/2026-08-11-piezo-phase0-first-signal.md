# ピエゾ実験機: 実機で初めて反応を確認した（phase0達成）

## 何を決めたか

保護回路込みの配線でGPIO4に接続したESP32-C3に書き込み、初めてピエゾの反応を
実機で確認できた。無入力時のベースラインはmin/maxの振れ幅(peak-to-peak)が
常時220〜240程度で、指で弾くとpp~700前後まで跳ねる——ベースラインから明確に
区別できることを確認した。[docs/piezo.md §4/§5](../piezo.md)を更新した。

## なぜ

書き込み・動作確認の過程で2つの技術的な問題を踏み、その場で解決した:

1. **USB CDCの設定漏れ**: ESP32-C3 SuperMiniはUSB-シリアル変換チップを積んで
   おらず、ネイティブUSBを`Serial`のCDCとして使うには`platformio.ini`の
   `build_flags`に`ARDUINO_USB_MODE=1`と`ARDUINO_USB_CDC_ON_BOOT=1`を明示する
   必要があった。無いと書き込み自体は成功する（esptoolのUSBダウンロードモードは
   別経路のため）のに、`Serial.print`がどこにも出ずSerialだけが沈黙する
   状態になり、原因の切り分けに手間取った。
2. **生値の出力が速すぎて読めない**: `analogRead`を毎サンプルSerial出力すると
   桁が変わる様子が流れて見えなかった。**100msごとのmin/max/振れ幅(peak-to-peak)
   だけを1行で出す**方式に変更し、10行/秒程度に落として可読にした。

デバイス接続時のトラブルシューティングとして、`/dev/tty.*`一覧にUSBデバイスが
出ない（→ケーブル/ポートの問題だった、データ線ありのケーブルに替えて解決）、
書き込み直後にポートが「busy」になる（→esptoolの残留Pythonプロセスが掴んで
いた、killして解決）も踏んだ。

## 何が覆ったか

- 当初の最小スケッチ（毎サンプルSerial.println）は実用上読めないと判明し、
  100ms窓のmin/max/pp集計版に置き換えた。

## 次に何が可能になったか

- phase0（反応するかの確認）が達成できたので、次はカンチレバー固定方法と
  おもりの選定という機械設計に進める（[docs/piezo.md §5](../piezo.md#5-次にやること)）。
- 無入力時のベースラインpp(220〜240)という具体的な基準値が得られたので、
  今後「明確な反応」をどの閾値で判定するかの目安にできる。
