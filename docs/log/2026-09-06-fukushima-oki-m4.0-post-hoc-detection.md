# 2026-09-04 福島県沖M4.0 事後解析

## きっかけ

ユーザーから「最近の地震で確認すべきものは？」と聞かれ、`tools/scan_quakes.py --days 7`で
機械的に候補を洗い出した。直近7日40件のうち唯一「投げる価値あり(境界帯)」に入ったのが
この地震で、`tools/detection_events.csv`にも`docs/log/`にも記録が無く未解析のまま
落ちていた（同日01:23の[宮城県沖M3.8](2026-09-04-miyagi-oki-m3.8-post-hoc-detection.md)は
解析済み、こちらは16:45で別の地震）。同じ走査で拾った
[茨城県沖M3.7](2026-09-06-ibaraki-oki-m3.7-post-hoc-detection.md)・
[青森県東方沖M4.7](2026-09-06-aomori-touhou-oki-m4.7-post-hoc-detection.md)と3件まとめての依頼。

## 震源要素（気象庁 list.json）

- 発生: 2026-09-04 16:45（分単位。秒は非公表）
- 震源: 福島県沖 N37.3/E141.2、深さ60km、M4.0、最大震度2
- 観測点（湯沢町）からの震央距離215km・震源距離223km（`--eew "37.3,141.2,60,2026-09-04 16:45"`）

M4.0の「投げる価値ありレンジ」115〜230km（[docs/detection_range.md](../detection_range.md)）に
対し223kmは**上端ぎりぎりの境界帯**。既存事例の`fukushima-oki-m4.0-2`(220km, warning)・
`fukushima-oki-m4.0-1`(273km, good)とほぼ同じ距離帯にあり、比較材料として価値があると判断した。

（レンジの数値は解析時点のもの。同セッション末に青森県東方沖M4.7をgoodとして追加し回帰を
再フィットしたため、現在の値は[docs/detection_range.md](../detection_range.md)を見ること。
この地震の判定は変わらない。）

## 自動検知の有無

`/events?all=1&size=20`で確認。直近イベントは2026-09-03 22:35(福島県会津M3.5)で止まっており、
9/4 16:45付近に自動検知イベントは無い。

|---|---|---|
| STA/LTA peak | 3.89 | 3.80 |

低帯域でSTA/LTA peakは3.8-3.9まで上がるが閾値4は未達で、しかもそのピーク位置は到達窓の中に
無い（浦河沖M6.0で見られた「低帯域に切り替えると到達窓のピークだけが跳ねる」形にならない）。
低帯域のSNRはむしろ1を割っており、到達窓は背景より静かですらある。

`--corr-bin`（20秒bin）でも、P窓・S窓に対応するt=[20,40)・[40,60)のfracは0.28/0.16
（背景0.17）と背景と区別できない。記録中で最も高いのはt=[60,80)のfrac=0.35だが、
これはS窓終了後の散発的な山で、前後のbinが0.05まで落ちるため到達窓に紐づく上昇とは言えない。

device単体プロット（標準設定）でも生波形・バンドパス後・スペクトログラムいずれも
到達窓の内外で見た目が変わらない。

## 判定: 完全埋没

標準・低帯域どちらでもSTA/LTAは閾値を一度も超えず、P窓・S窓・コーダ想定域のSNR・直線性、
2機の直線性相関いずれも背景と分離できなかった。

**境界帯（レンジ115〜230kmの上端223km）でも埋没する実例**として意味がある。同じ福島県沖の
M4.0でも震源距離273kmの`fukushima-oki-m4.0-1`はgood判定だったので、距離とMだけでは説明の
つかない分散（方位・放射パターン・その時の背景ノイズ）が改めて確認された形になる——
[docs/detection_range.md](../detection_range.md)が「目安であって保証される検出円ではない」と
書いている通りの事例。
