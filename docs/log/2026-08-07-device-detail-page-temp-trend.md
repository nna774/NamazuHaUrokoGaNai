# デバイス詳細ページとセンサ内蔵温度トレンドを追加した

## 何を決めたか

ダッシュボードの「デバイス」タブに、行クリックで飛べる個別ページ`#device/<id>`を追加し、
そこにセンサ内蔵温度のトレンドチャートを置いた。一覧テーブル自体には列を足さない。

温度データは新設の api エンドポイント`GET /devices/<id>/temp?hours=<n>`が返す。中身は
`lambda/common/store.py`の`load_temp_series()`が組み立てる。

## なぜそう決めたか

### 温度を波形と同じ画面・同じ軸に乗せない

温度トレイラー(`docs/wire_format.md`)は30秒〜数十秒に1点で、狙いは分〜時間スケールの
架台の熱ドリフト検知。100Hzの加速度波形とはサンプル間隔が3桁違う上、生値は校正値では
ないので絶対値は信用できない。ライブビューに重ねるには時間軸のリサンプルや2軸表示が
要り、実装コストの割に「今すぐ要る」機能ではないと判断した。

### 一覧テーブルに列を足さない

最初はdevicesタブの一覧行に温度列を足す案を検討したが、ユーザーから「一覧ページに
これ以上詰め込むのは苦しい」との指摘があり、個別ページに切り出す案に転換した。
`#event/<id>`と同じ「一覧⇔詳細の排他表示＋ハッシュルーティング」パターンが既にある
ので、それをそのまま`#device/<id>`に流用できた。詳細ページは今後（方位較正値など、
`docs/device_overlay.md`の未決事項）を置く箱としても使える。

### 温度取得はヘッダ+トレイラーだけの Range GET にした

波形と同じ`load_window`の作りをそのまま流用すると、温度1点のために1バッチ数十KBの
加速度ペイロード全部を読むことになる。api は認証なし公開なので、窓を広げるほど
S3 GET数が線形に増える設計は避けたい（`/recent`が30分上限でガードしているのと同じ
理由）。そこで`wire.parse_header()`を新設し、まずヘッダ32バイトだけ Range GET して
`sample_count`から payload 長を逆算、続けてトレイラー領域だけを2回目の Range GET
（`bytes=<offset>-`、末尾まで）で読む。ペイロード本体は一切転送しない。

これにより、キー数が`max_points`(既定300)を超えたら間引く間引き込みと合わせて、
温度の窓を24時間まで許容できるようにした（波形の30分上限よりずっと緩い）。

### v1バッチ(トレイラー無し)の扱い

v1バッチはペイロード末尾がオブジェクト末尾と一致するので、トレイラー領域への
Range GETは実S3では416(Invalid Range)になる。`parse_trailer`が「壊れたトレイラーは
補助情報だから波形ごと捨てない」という方針を持っているのと同じ考え方で、
`load_temp_series`もこの例外を「温度なし」として握りつぶす。

### 換算℃はセンサ種別で出し分ける

`wire.temp_c(meta)`を新設し、`sensor_type == SENSOR_TYPE_ADXL355`の時だけ
`adxl355_temp_c()`を適用する。IIS3DHHC機（1号機）はそもそも`readTemperatureRaw()`が
未実装で温度トレイラー自体を積まないが、将来別センサが温度を積んでも誤った換算式を
当てないよう、api は raw値と一緒に「換算できる時だけ`c`を付ける」形にした。

## 何が覆ったか

なし（新規追加）。既存の`/recent`・`/events`・`/event`・`/devices`エンドポイントは無変更。

## 次に何が可能になったか

- デバイス詳細ページという箱ができたので、`docs/device_overlay.md`の方位較正値
  （`azimuth_deg`等）や、今後増える機体固有パラメータの表示先として使える。
- **ライブビューへの温度重ね描き案は実装していない。** アイデアとしてここに残す:
  加速度波形と同じ画面に温度を重ねられれば、[docs/device_overlay.md](../device_overlay.md)
  §1.4で踏んだ「シーリングファンが2号機だけ汚染していた」ような、ノイズ増加と温度上昇の
  相関を波形を見ながら直接確認できる。ネックはサンプル間隔の3桁差（波形100Hz・温度
  30秒に1点）の解決（リサンプルか2軸グラフ）で、詳細ページのシンプルな折れ線より
  実装コストが高い。優先度が上がったら着手する。

## 動作確認

- `pytest lambda/tests`: 86件（新規17件を含む）全通過。
- ダッシュボードはモックAPI(`python3 -m http.server`+スタブJSON)を立てて実ブラウザで
  確認: デバイス一覧→行クリックで詳細へ遷移、温度トレンド折れ線描画、期間セレクタの
  切替による再取得、`#device/2?h=24`のような直リロードからの状態復元、温度非対応機
  （1号機想定）での「データなし」表示、いずれも意図通り。コンソールエラーなし。
- **実機・本番APIでの動作確認はまだ**（このログの時点でterraform applyもdashboard
  デプロイも未実施）。
