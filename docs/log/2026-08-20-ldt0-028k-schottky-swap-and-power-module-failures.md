# LDT0-028K、ショットキーダイオードに交換してクランプ挙動を確認し、電源モジュールが2台連続破損した原因を分析した

[前回](2026-08-19-ldt0-028k-protection-circuit-breadboard-debug.md)決めた方針通り、D1・D2を
1N60からショットキーダイオードへ交換した。届いたダイオードセットには1N5817・1N5818・1N5819
（VRRM 20V/30V/40V）が入っており、**この電流域(サブmA)ではVfの差はほぼ無視できる一方、
逆耐圧のマージンは大きい方が安全**という判断で、D1・D2とも1N5819に統一した。

## AC結合の罠でD1が壊れていると誤診しかけた

交換直後、D1単体でのテストが「Vmaxが0.24V止まり」というD2のような挙動を示し、一時
「D1がまだ逆向きなのでは」「配線がGNDに繋がっているのでは」と疑って導通チェックまで
行った。**結果、D1の3.3Vレールへの接続自体は正しいと確認できた。**

原因はもっと単純だった——**AC結合(直流成分を除去する設定)のまま見ていたため、実際は
+1.2V付近に持ち上がっていた直流バイアスを基準点として表示しており、絶対的なクランプ挙動
(3.3V+Vf付近で頭打ちになっているはずの値)が正しく見えていなかった**。DC結合に切り替えて
測り直したところ、D1単体でVmax=3.48V(絶対値)と、想定通りのクランプ電圧が確認できた。
**D1は最初から正常に機能していた。** AC結合はオフセットが大きい状況では絶対値の解釈を
誤らせる、という教訓が残った。

D1・D2両方を挿した状態(DC結合)では**Vmax=3.48V, Vmin=-0.08V**——D1・D2とも設計通りの
範囲でクランプできていることを確認した。

## +1.2Vの直流オフセットは、Rbの超高インピーダンスとショットキーの逆リーク電流の組み合わせ

平常時(叩いていない状態)でもノードBに+1.2V程度の直流バイアスが乗っていた。これはRbの
値(500MΩ級)が極端に大きいため、**ショットキーダイオード特有の(PN接合ダイオードより
多めの)逆方向リーク電流が、Rbを通して電圧に増幅されてしまう**ことが原因と判断した。
ナノアンペア級のリーク電流でも1V以上のオフセットを作るには十分な計算になる——50Hzノイズを
拾いやすかった件と同じく、**Rbを極端に大きくしたことの副作用**という位置づけになる。
D1を並列2本に増やしたところオフセットが+2.1V付近まで悪化したことも、リーク電流が
ダイオード数に比例して増える、という理屈と整合していた。

## Vmaxのマージン改善: Rs増加は無効、並列ダイオードには副作用

D1のクランプ電圧(3.48V)はESP32の絶対最大定格(目安3.6V)に対してマージンが0.12Vしかなく、
複数回の強めのタップで毎回この値に張り付いていた。マージンを広げるため2つの対策を試した:

- **Rsを220kΩ→470kΩに倍増**: Vmaxは3.48Vのまま**全く変化しなかった**。クランプ電圧は
  Rsによる電流制限では決まっておらず、別の要因(ダイオード自体の特性やピエゾ自身の
  静電容量が効く速い過渡電流)が支配的だと分かった
- **D1を並列2本に増設**: 電流を分担させてVfを下げる狙いだったが、Vmax低減の効果を
  確認する前に電源トラブルで中断した。直流オフセットが悪化する副作用(上記)は確認済み

## 電源モジュールが2台連続で故障した原因: 電流の大きさではなく寄生経路のトリガー

セッション中にブレッドボード用3.3V電源モジュールが2台とも、最初は正常だったのに
テスト中に異常電圧(12V、次いで9V)を出すようになる故障を起こした。単発の個体不良では
なく、**回路側がモジュールを壊している**と判断した。

当初「D1のクランプ電流がRb経由で3.3Vレールへ逆流し、レギュレータを破壊した」という
仮説を立てたが、`ピエゾ100V ÷ Rb(500MΩ) = 0.2µA`程度にしかならず、この電流量では
熱破壊の説明がつかないと指摘を受け、説明を訂正した:

- クランプ電流はRb経由ではなく、Rs+ピエゾ自身の静電容量(C≈480pF)による過渡電流
  (`I=C×dV/dt`)で決まるため、実際はサブmA程度(Rs設計時の見積もりと同オーダー)
  ——とはいえこれも部品を熱破壊するほどの電流ではない
- **本質的な破壊メカニズムは電流の大きさではなく、「Voutが一瞬でもVinを超えると
  レギュレータIC内部の意図しない寄生経路が開き、そこから本来の電源(USB等)側から
  もっと大きな電流が流れて破壊に至る」という、安価なリニアレギュレータでよく知られた
  故障モードだと考えられる**。トリガーになる注入電流はごく僅かでも、実際に壊れる時の
  電流はICの寄生構造次第で全く別物になりうる

対策として、D1近くの3.3VレールとGND間に**バルクコンデンサ(10〜100µF)を追加し、
注入された電荷を局所的に吸収してVoutが実際にVinを超えないようにする**方針にした。
可能ならレギュレータのVin-Vout間に逆流保護ダイオードを足すことも検討する。

**この一件で、「ESP32本体の3.3Vピンを間借りする」という以前の代替案は保留にした**——
壊れても被害の小さい安価な電源モジュールと違い、ESP32は本番用に払い出した実機であり、
同じ壊れ方をするリスクを検証無しに冒すべきではないと判断した。

## 次にできるようになったこと

新しい電源モジュールを無負荷で健全性確認 → バルクコンデンサ(・可能なら逆流保護
ダイオード)を追加 → 3.3Vレール自体をオシロで監視しながら叩いて逆流の影響が
緩和されているか確認、という順で電源側の対策を先に固める。それが確認できてから
並列D1のVmax改善効果を再測定し、GPIO4への実接続を判断する。
