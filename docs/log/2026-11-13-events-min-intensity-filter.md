# 2026-11-13 イベント一覧に「震度n以上」の絞り込みを足した

## 決定

- `/events` に `min_intensity=<計測震度>` を足し、`events.list_page()` で
  `effective_intensity >= min_intensity` のものだけ返す。ダッシュボードは一覧に「震度」セレクタ
  （すべて/1以上/2以上/3以上/4以上/5弱以上）を置き、URL `#events?mi=` に載せる。

## 理由

- **サーバ側で絞る。** 一覧は20件ずつのサーバページングなので、クライアントで落とすと
  ページごとに件数がばらつき、総件数も合わなくなる。既存の `device` 絞り込みと同じ置き場所。
- **判定は `effective_intensity`。** 一覧に表示している震度と同じ値で絞らないと、「震度3以上」に
  したのに確定震度1が混ざる（速報 `max_intensity` だけ大きいケース）といった食い違いが出る。
- **パラメータは階級でなく計測震度の下限。** 「5弱」「5強」のような文字列をAPIに持ち込まず、
  階級→下限値の対応はダッシュボードの選択肢側に閉じ込めた（震度n以上 = n-0.5、5弱以上 = 4.5）。
  5強以上の選択肢は、自宅でそこまで揺れたイベントがまだ無いので置いていない。
- `/events` はCloudFrontでキャッシュしていない（default behavior=CachingDisabled・全クエリ転送）
  ので、キャッシュポリシーのwhitelist変更は不要。
