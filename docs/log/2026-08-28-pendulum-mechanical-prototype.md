# 2026-08-28 振り子型質量-バネ系の機械設計・部材選定・仮組み試験

前日([docs/log/2026-08-27-sensor-pickup-bringup-firmware.md](2026-08-27-sensor-pickup-bringup-firmware.md))で
SS49E・MLX90393の机上確認(合格)と、振り子+MLX90393(Bx/By)という配置方針を
固めた。本セッションはその先——**実際に振り子を組む部材の選定と、仮組みでの
試験**。まだ最終形には至っておらず、次セッションへの引き継ぎ用に途中経過を残す。

## 何を決めたか

### アーム(振り子を吊る片持ち梁)

- **材質・寸法: 杉(または檜)の角材、30×30×600mmを25×25/25×30/25×45より優先する。**
  片持ち梁の曲げ剛性は「曲がる方向の断面の厚み」だけで決まり、直交方向の幅は
  効かない。25×25・25×30・25×45はどれも最弱方向の厚みが25mmで共通なので、
  最悪ケースの固有振動数は実質同じ(杉・600mmで概算49Hz)。**30×30は全方向で
  30mm厚になるので、最悪ケースでも約59Hz(先端無負荷)——重さは140g→200gに
  増える程度で、デメリットが無い。**
- **先端に付く質量(錘一式)が効くことに注意。** 先端に100g乗ると実効固有振動数は
  30×30で約34Hz・25×25で約25Hzまで下がる概算になる(目標は10Hzの3〜5倍=
  30〜50Hz以上)。**錘・固定具はなるべく軽く保つか、マージンが薄いと感じたら
  アームを短く切って稼ぐ**(周波数は長さの2乗の逆数で効くので400mmに詰めれば
  600mmの2.25倍になる)。
- **固定方法が周波数を支配する。** 上記の計算はすべて「根元が完全固定」前提。
  ただ置く/軽く仮止めするだけだと根元に回転の遊びが生まれ、実効剛性が
  1/100になれば周波数は1/10まで落ちて、狙っている1-10Hz帯のど真ん中に
  共振が来かねない。**共振周波数を実測する目的なら、Fクランプや木ネジで
  ちゃんと締め付けてから測ること**——「とりあえず仮組みで動くか見る」段階
  なら置くだけでも良いが、その結果からアームの合否を判断してはいけない。

### 吊り点の金具

- ヒートン(木ネジ+アイ)やS字フックは吊り点そのものとしては使えるが、
  **鋼製なので磁石・センサへの近さは要考慮**(後述の「教訓」参照)。
- **錘がアーム本体にぶつからないよう、金折/隅金(L字の接合金具)をアームから
  横に張り出す向きに取り付け、その先端を吊り点にする案を採用。** 片方の羽を
  アームにネジ2本以上(1本だとネジ周りに回転の遊びが生まれる)で固定し、
  もう片方を空中に向けて突き出す。これで振れる方向すべてでアーム本体からの
  クリアランスが確保できる。張り出し長さは、まだ質量-バネ系のストローク量が
  分かっていない段階なので、余裕を持たせて後で詰められるようにしておく。

### 糸・錘の選定と実購入

- **糸: 東レ(TORAY) ライン 道糸 銀鱗 50mパッケージ品(1号程度の細め)。**
  [https://www.amazon.co.jp/dp/B07Y55QL12](https://www.amazon.co.jp/dp/B07Y55QL12) ¥573で購入済み。
  非磁性(ナイロン)・低伸度・細いほど捩れ剛性が下がり錘の回転(磁石の向きが
  ぶれる原因)を防げる、という条件で選定。鋼線は磁石のすぐ近くに常時ある
  ことになるため明確に除外。
- **錘: おもり 釣り 中通し リード 3g/5g/10g/15g/20g 各5個入 ナツメ型。**
  [https://www.amazon.co.jp/dp/B0CFQKQWQ6](https://www.amazon.co.jp/dp/B0CFQKQWQ6) ¥658で購入済み。
  非磁性(鉛)・中通し(糸を通す穴が最初から空いている)・グラム単位で
  20〜50gの狙い目レンジを組み合わせられる、という条件で選定。目標重量は
  「アームの共振マージンを削らない程度に軽く、かつ風などの空気の揺らぎで
  直接励振されない程度に重い」のバランス(ピエゾ実験機で実際に踏んだ
  風による誤励振問題[docs/piezo.md]と同じ懸念に基づく)。

## 教訓: 磁石はブレッドボード・ヘッダピンの鋼材も引き寄せる

仮組み試験中、磁石がESP32の余ったヘッダピンやブレッドボード内部の鋼材に
物理的に引っ張られていることが判明した。単なるノイズ的な影響(2026-08-27の
残留磁化の話)ではなく、**振り子の平衡位置そのものを歪める、より直接的な
力学的干渉**という点で質が違う。

対処方針として2つを組み合わせる:

1. **磁石を弱める**(手持ちの磁石が小粒を複数直列にした構成のため、個数を
   減らすのが容易)。吸着力は磁石の強さの**2乗**、センサの感度信号は**1乗**
   でしか効かないため、磁石を弱めると吸着力の方が優先的に減る——有利な
   トレードオフ。ただし固定のしやすさ(直列個数を確保していた理由)との
   兼ね合いがあるので、減らしすぎに注意しながら試す。
2. **ブレッドボード・ESP32本体を振り子の可動域から物理的に遠ざけ、SS49E
   センサだけを配線を伸ばして近くに残す。** 電気的にはSS49Eの3本さえ届けば
   よいので、電子部品の塊(基板)と、mm オーダーの隙間が要るセンサ本体は
   分離して考えられる。吸着力は距離に対しかなり急峻に落ちるため、数cm離す
   だけでも効果が期待できる。

まだ両方とも実施・効果確認の途中。

## 机上確認の仕組み側でやったこと

### SS49Eのサンプルレートを2kHzへ

アームの共振周波数(想定30〜50Hz)をリンギング波形として読み取るには、
経験則で目標周波数の5〜10倍(250〜500Hz以上)のサンプリングが要る。
MLX90393(I2C、変換時間・プロトコルオーバーヘッドあり)ではなく、
**analogReadで単純に速く回せるSS49Eをこの測定に使うことにし**、
`firmware/src/hall_main.cpp`の`kSampleIntervalUs`を100Hz(10000)から
2kHz(500)へ引き上げた。実機で約2050サンプル/秒が実際に出ることを確認済み。

### `tools/live_scope.py`を新設

毎回シリアルログをファイルに落として手作業で解析するのが非効率だったため、
波形とFFTをリアルタイム表示するツールを作った。`t_us,raw,...`形式のCSVを
吐くファームであればセンサ非依存で使える汎用スクリプト。

```bash
python tools/live_scope.py --port /dev/cu.usbmodem101
```

サンプルレートはタイムスタンプの中央値から自動推定するので、ファーム側の
サンプル間隔を変えても指定し直す必要がない。

**不具合と修正**: 放置していると波形が0に張り付いたまま復帰しない症状が
発生。原因は、2kHzで送信し続けている最中に描画側の読み出しが一瞬詰まると
ESP32-C3側のUSB CDC送信バッファが埋まり`Serial.printf()`がブロックし続けて
最終的にウォッチドッグでリセットがかかり、`micros()`が0近くへ巻き戻る
こと。再起動前後のタイムスタンプが混在すると、差分の中央値からの
サンプルレート推定が壊れたまま自己回復しなくなる。**タイムスタンプの
巻き戻りを検出したらバッファを自動的に初期化する**よう修正した(コミット
`98efe37`)。

## 実機での観察(仮組み・位置調整前)

- 2kHzでの叩き試験では、まだ明確な高速リンギングは見えていない
  (位置・隙間の調整前のため想定内)。
- 振り子を大きく振らせた波形をキャプチャしたところ、正弦波的ではなく
  近接時に鋭いスパイク・遠方でなだらかな谷という非対称な形が見えた。
  **これは物理的な接触の証拠ではなく、1/r³という近接場の強い非線形性が
  振れ幅の大きい状態でそのまま波形に出ている可能性が高いと判断した**
  (2サイクル分の波形の形がほぼ同じで、接触由来の不規則さが見られなかった
  ため)。ただし磁石がブレッドボードに吸着している事実もあるため、両方が
  混ざっている可能性は残る——見た目/音で直接確認するのが最終的な切り分け
  手段。磁石を弱める作業はどちらの原因にも効くため、その結果を見て判断する。
