# 2026-08-28 「コーダ想定域」窓・常時corr-binを既存の全事例に当ててみる

[コーダ想定域窓・`--corr-bin`常時出力の実装](2026-08-28-coda-window-and-corr-bin-default.md)の後、
ユーザーから「今の状態で他のeventはどうなるか」と聞かれ、既存の事後解析11件全部
（`福島県沖(旧)`・`熊本地震`は当時device2が未稼働のためdevice1単独）を新しい
`tools/detectlab.py`で撮り直した。図は[img/](img/)に`2026-08-28-coda-window-recheck-*.png`
として残す。

## 結果

**verdictが変わったのは実質1件（[福島県沖M4.5](2026-08-26-fukushima-oki-m4.5-post-hoc-detection.md)）のみ**——
これは本チェックの前に別途`--corr-bin`のbin別集計で「弱いprobable」へ格上げ済みで、
今回のコーダ想定域窓（両機とも自動で「地震らしい」）は追認する形になった。

その他は概ね現状維持だったが、**1件だけ紛らわしい結果**が出た:

- **茨城県沖M3.5**: コーダ想定域（S窓終了から180秒）でdevice2が単純な窓平均で
  「地震らしい」（SNR=1.53・直線性=0.71）と出た。一見すると格上げ材料に見えたが、
  `--corr-bin`のbin別集計と図（[img/2026-08-28-coda-window-recheck-ibaraki-oki-m3.5.png](img/2026-08-28-coda-window-recheck-ibaraki-oki-m3.5.png)）
  を見ると、**コーダ想定域のほとんどの区間（t+80〜240s）は背景と同水準か以下**——
  S窓直後（t+40〜80s）だけが突出しているだけだった。180秒全体の平均だと局所的な
  高さに引っ張られて「地震らしい」に化ける、という
  [`docs/post_hoc_detection.md`に書いたコーダ想定域の注意点](../post_hoc_detection.md)
  （180秒は固定値・全体平均は粗い）の実例になった。**判定は「弱いprobable／境界線上」で
  据え置き。**

## 分かったこと

新機能は狙い通りの2つの働きをした——**既存の判定を静かに裏付ける**（浦河沖・三陸沖・
福島県沖M4.5）のと、**嘘の当たりも見せる**（茨城県沖M3.5）。後者が特に有益で、
「窓の平均だけで判断せずbin別を見ろ」という注意点が絵に描いたような形で実証された。
`detection_events.csv`の変更は不要（福島県沖M4.5の格上げは既に反映済み）。
