# ドキュメント本体に居座っていた経緯記述を刈り込んだ

ユーザーから「docsがごちゃついてきた、経緯の追記が多くて長くなっている」と
指摘を受け、`docs/design.md`・`docs/noise.md`・`docs/piezo.md`・`docs/adxl355.md`
を対象に、本体ドキュメントに残っていた日付付きの調査経緯・実験過程の記述を
圧縮した。

## 何が問題だったか

CLAUDE.mdは元々「ログは経緯、本体は現在の結論」という原則を掲げていたが、
実際の編集では追記が先行し、古くなった経緯を刈り込む工程が抜け落ちていた。
最も酷かったのは`design.md`の「送信の信頼性」節で、433行中180行(4割)が
「新しい仮説(2026-08-08)」「未検証」「実バックトレースで確定(2026-08-29)」と
いう推理の紆余曲折の積み重ねになっており、今の結論を知りたいだけの読み手が
全部読まされる構造になっていた。同じ傾向は`noise.md`の「測定ログ（暫定）」、
`piezo.md`の「【現状・実験中】」節、`adxl355.md`のトラブル記述にもあった。

## 何をしたか

- **design.md**: 「送信の信頼性」節(230-424行)を、バッファの多段構成・
  ネットワークI/Oのタイムアウト予算・可観測性・coredump自動送信、の4小節に
  再構成し、現在の結論だけを残した。推理過程は既存の`docs/log/*.md`への
  リンクに委ねた。副次的に、kMaxRamBatchesの値が本文(6→3本)と実際の
  `firmware/src/config.h`(現在値2)で食い違っていたのに気づき、config.hの
  コメントを参照する記述に直した——古い経緯がそのまま残ると値がずれても
  気づけない、という今回の問題そのものの実例。
- **noise.md**: 「測定ログ（暫定）」節のうち、2026-08-02の初回サニティ
  チェックは要点だけに圧縮（IIS3DHHCとの粗い比較表は、より厳密な
  2026-08-05の同時刻比較で実質置き換わっているため削除）。「何が分かったか」
  「残るドリフトへの対策候補」の長い考察も要点だけに絞った。他ドキュメント
  から`#見出し`で参照されている節(2026-08-05・2026-08-11の比較、残る
  ドリフト対策候補)は見出しテキストを変えずデータ表はそのまま残した。
- **piezo.md**: 「運用開始後の観測」を要点だけに圧縮。§9の「既存Z軸側の
  設計」と「【現状・実験中】C=100nFへ半減」の2節を1節に統合し、実験の
  紆余曲折（200nF→切り分け実験→100nFへ半減→タイミングアーティファクトの
  誤判定の教訓）を「現在の値と根拠」だけの記述に圧縮した。
- **adxl355.md**: §5.1.1の「SPI読み取り不良」に付いていた2026-08-29の
  追記2本(TASK_WDT関連の完全に別の欠測問題の調査過程)を、design.mdへの
  リンク1行に置き換えた——この内容は既にdesign.md「送信の信頼性」に
  統合済みで、ここに残す理由が無かった。§9「検証実行時の段取り
  （2026-08-04実施予定）」は既に実行済みの一度きりの手順書で、§6の
  検証フローと内容が重複していたため削除した。

## 確認したこと

- 各ファイルからの外部アンカー参照(`file.md#見出し`)を事前に洗い出し、
  参照されている見出しテキストは変更しなかった
  （`design.md#送信の信頼性`、`noise.md`の2026-08-05/08-11関連見出し、
  `piezo.md`の§4/§6/§7/§9、`adxl355.md`の§7.1/§7.3.1）。
- doc-link-checkはGo未インストールのためローカル実行できず、代わりに
  Pythonスクリプトで4ファイル内の相対リンクがファイルとして存在するかを
  確認した。今回の編集起因の壊れリンクは無し（`adxl355.md`に1件
  pre-existingな壊れリンクを発見したが、今回のスコープ外のため未修正）。

## 次に何が可能になったか

4ファイル合計で272行(design.md 433→346、noise.md 355→318、piezo.md
528→446、adxl355.md 396→341)の純減。同じ基準での刈り込みは他の大きい
ドキュメント(`ota.md`・`STATUS.md`等)にも適用できる余地があるが、今回は
ユーザーから指定された4ファイルの範囲に留めた。運用ルールとして「経緯の
刈り込み」をCLAUDE.mdに明文化する作業は別PRで行う。
