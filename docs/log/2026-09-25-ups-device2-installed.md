# 2026-09-25 UPSセットをdevice2に実装した

[2026-09-15の充電完了観測](2026-09-15-ups-charge-completion-ok-observed.md)までで電気的な
動作確認は一通り終えており、物理的な設置と実機への接続を行った。

## 分かったこと・決めたこと

1. **物理的な固定方法**: device2本体がそもそもコンクリートブロック上にブレッドボードを
   置いただけの構成なので、UPS側だけ専用の筐体を用意する必要は無いと判断した。18650用の
   バッテリーボックス(バネ接点、取り外しはやや面倒だが接触信頼性は高い)とLFUPSMA基板を
   それぞれ既存の設置場所へ固定する方針にした。将来のセル交換(§2の予備セル運用)が
   多少面倒になるトレードオフはあるが、緊急性の低い作業なので許容
2. **過放電で劣化するリスクは許容範囲と判断した**。[2026-09-14の放電試験](2026-09-14-ups-discharge-test.md)で
   「電池が本当に負荷から切り離されるか」は未判別のままだったが、LiFePO4を選定した
   理由(§0、熱暴走しない・安全に壊れる化学種)に立ち返ると、過放電で起きるのは劣化で
   あって発火等の危険ではない。予備セルもあるため、最悪の場合はセル交換で済む
3. **LFUPSMA OUT+/OUT- → ESP32(TTGO T-Display)のUSB-Cポート**の接続には、USB-Cの
   電源線(赤/黒)だけが出ているブレイクアウトケーブルを使った。IN側(§2)と同じ
   「裸線ピグテールで壁アダプタ相当の給電を模す」発想の踏襲
4. **極性確認は電圧測定ではなく導通(シェル)確認で行った**。当初は充電器に挿して
   赤黒間の電圧を測る方法を考えたが、実際に試すと0.8V程度しか出ず——これはUSB PD対応の
   「賢い」充電器がCC1/CC2のピン信号を見て出力の可否を判断する仕様のためで、電源専用の
   裸線ケーブルにはCC線が無くVBUSが解放状態になっていたと判明。極性の誤りではなかった。
   代わりに**黒線とUSB-Cプラグの金属シェル(規格上ほぼ常にGND)との導通**を確認する方法に
   切り替え、黒=GND・赤=VBUS(+)を確定させた。なお、このCC negotiation問題は実際の
   接続先(ESP32のUSB-Cポート)には無関係——[TTGO T-Displayの回路図](https://github.com/Xinyuan-LilyGO/TTGO-T-Display/blob/master/schematic/ESP32-TFT(6-26).pdf)を
   確認したところ、VBUSはショットキーダイオード`D2`を経て`AP2112K-3.3V`レギュレータへ
   直結されるだけで、CC信号によって出力の可否が決まるような能動的なゲートは無いと
   分かっている
5. **接続・設置を完了し、device2をUPS経由の給電へ切り替えた**
