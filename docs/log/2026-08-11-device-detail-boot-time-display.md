# デバイス詳細ページに「起動時刻」行を追加

稼働時間(`uptime_s`)は一覧・詳細の両方に出ていたが、絶対の起動時刻(`boot_epoch_us`)は
APIレスポンスに入っているのに画面には出ておらず、見る側が「現在時刻－稼働時間」を
頭で計算する必要があった。ユーザー指摘で判明。

## 変更

`dashboard/app.js`の`renderDeviceInfo()`に「起動時刻」行を1つ足した（`稼働時間`行の直前）。
`最終受信`行と同じ`toLocaleString('ja-JP')`で`boot_epoch_us`をそのまま日時表示するだけ。
相対表記（`fmtAgo`系）は付けない——これは「現在との差」ではなく絶対時刻そのものを
見せるのが目的の行なので、他の行に合わせて相対表記を足すと本末転倒になる。
`boot_epoch_us`が無い（旧ファーム）場合は`稼働時間`と同じく「不明」。

一覧テーブルには追加していない。列がすでに8つで480px以下では累計バッチ・版数を
隠す設計になっており（[progress.md](../progress.md)2026-08-07）、これ以上絶対時刻の列を
足すと一覧の狭さがさらに悪化する。起動時刻を見たい場面は個別デバイスを掘り下げて
調べる時なので、詳細ページだけで十分と判断した。

## 確認

本番API（`https://api.namazu.dark-kuins.net`）に向けたローカルsyncサーバ
（`python3 -m http.server`、`?api=...`クエリで向き先指定）でdevice0001の詳細ページを
実際に開き、「起動時刻: 2026/8/11 8:30:53」「稼働時間: 5時間(21289秒)」が並んで
出ることを確認した。読み取り専用のAPIなので本番に触っても副作用は無い。
