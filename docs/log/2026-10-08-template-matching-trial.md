# 事後解析へのテンプレートマッチング導入の試行

## 動機

機間の直線性相関は「1号機が背景ノイズに埋もれる弱い地震」では構造的に上がらず、2号機だけに信号がある
ケースを格上げする根拠として使えない（無いことが否定にならない片側の根拠）。単独観測点で微小地震を拾う
既知の手法としてマッチドフィルタ（テンプレートマッチング）があるので、使い捨てスクリプトで試した。
題材は[千葉県東方沖M3.9(04:36)](2026-10-08-chiba-toho-oki-m3.9-0436-post-hoc-detection.md)（warning、埋没寄り）。

## 方法

- テンプレート: 千葉県北東部M4.8(10-08 04:13)の各デバイスの記録、04:14:22から80秒（3軸）。
  0.5-2Hzと1-10Hzの2帯域、device1・device2それぞれ自機のテンプレートを使う
- 統計量: 3軸合算の正規化相互相関(NCC)。発生分の0〜130秒後に当たるラグ窓での最大値
- **有意性は位相ランダム化テンプレート30〜40本との比較（z値）で見る。** 背景ノイズの分布だけと
  比べると、別地域(福島県沖・茨城県北部)でも9〜14MAD相当に立ってしまい、波形固有の一致ではなく
  「地震らしい帯域のエネルギーがある」だけを拾っていた。偽テンプレートは同じ振幅スペクトルで波形だけ壊す
- 対照: 同震央付近(0〜11km)の過去の地震7件（気象庁一覧から。M3.0〜5.1）
- 偽陽性率: 地震と無関係な窓(1窓110秒、各構成で316〜324窓)で同じzを計算

## 結果

初回は使い捨てスクリプトで回したが、**テンプレートの切り出し位置が間違っていた**。読み込んだ窓の
先頭が指定時刻ちょうどだと仮定して先頭22秒を捨てていたが、実際の先頭はデバイスごとにずれる
（バッチ境界）。そのためテンプレートが機ごとに数秒違う位置から切られ、**「ピークのラグがデバイス間で
約10秒ずれる」という未解明の現象はこの不具合の産物だった**。読み込み窓の実際の開始時刻から
切り出すよう直した`tools/template_match.py`で全て取り直したのが下表（上の初回値は破棄した）。

| 対象 | dev2 低帯域 | dev2 1-10Hz | dev1 低帯域 | dev1 1-10Hz |
|---|---|---|---|---|
| **千葉県東方沖M3.9(04:36)** | **+3.3** | **+5.1** | **+3.0** | **+4.6** |
| M3.6 09-24 17:27 | +2.1 | +0.7 | +1.9 | +0.9 |
| M3.6 10-01 21:31 | +0.7 | +2.1 | +0.8 | +2.1 |
| M3.5 10-01 06:17 | 0.0 | +1.8 | +0.6 | +3.4 |
| M3.8 09-27 09:45（以前critical） | +0.1 | +1.3 | +0.7 | +1.5 |
| M3.3 10-01 21:51 / M3.0 09-29 22:48 | +1.3以下 | | | |
| M5.1 10-01 21:27 | 0.3以下（低帯域は負） | | | |

偽陽性率（無関係な窓でz超過が出る割合、各構成で316〜324窓）: z>2.8 が0.9〜1.9%、z>3.5 が0.3〜1.2%。

- M3.9は4構成すべてで偽テンプレート全本を上回り(0/30)、対象群の中で最大。**ピークのラグも両機で
  +51〜54秒に揃った**（修正前は10秒ずれていた）。独立した2機・2帯域で同じ時刻に立つので、1窓あたり
  1%前後の偽陽性率に対して偶然とは考えにくい。ただしデバイス間は環境ノイズを共有しうるので
  厳密に独立とは仮定できない
- ただしこの手法は**感度が低い**。同震央の他の7件のうちz>3を超えたのは M3.5 10-01 06:17 の
  dev1 1-10Hz(+3.4)の1構成だけで、他は2.1以下。0kmの同震央・同深さだった09-27 M3.8（以前critical）も
  拾えない。M5.1も一致しない（波形が再現しない）。M3.9が拾えたのは「当たった」側で、一般に効くとは言えない

## 決めたこと

- **M3.9のverdictは`warning`のまま据え置く。** 追加の根拠としてはかなり有力になった（ラグの不整合が
  解消し、両機・両帯域でz>3）が、(a)対照の感度が低く、拾えるケースが限られる、(b)境界ケースを
  選んで試した事後の検定である、ため`good`へ上げる判断はユーザーに委ねる
- 「2号機だけprobable」という判定語彙は今回は足さない。4件のどれにも「2号機だけ有意」という純粋な例が
  無く、実例が出てからで遅くない
- テンプレートマッチングは**同地域の検出済みテンプレートがある時の補助判定**として手順書に記載する。
  `tools/template_match.py`として単体CLIにして置いた（2号機だけ有意に出そうな事例が出た時に使う）。
  `detectlab.py`への組み込みは実例が溜まってから
- 教訓: 時刻ずれのような機構的な不具合は、「機間で結果が食い違う」という形で出る。未解明のずれは
  理由を付けずに放置せず、まず切り出し位置などの前処理を疑うこと
