# 2026-08-26 茨城県南部M3.4 事後解析

`tools/scan_quakes.py`（[2026-08-28の実装](2026-08-28-scan-quakes-jma-feed.md)）が
気象庁の地震一覧から「投げる価値あり」として拾った候補。ユーザーの指示で確認した。

## 震源要素

気象庁`list.json`より: 発生 2026-08-26 08:33頃(秒不明) JST、震源 N36.1/E139.9、
深さ50km、M3.4、最大震度2、震央距離134km・震源距離143km。

## 1. 自動検知の有無

`/events?all=1&size=20`を確認したが該当時刻付近に`event_id`は無い
（前後は08-23 22:45と08-27 04:23で、08-26は空白）。

## 2. detectlab解析

### 標準設定（3軸・1-10Hz）

```
device=1  STA/LTA peak=3.25（閾値未達）
  P窓 SNR=0.99 直線性=0.50 → 微妙 / S窓 SNR=1.03 直線性=0.45 → 微妙
device=2  STA/LTA peak=4.81（閾値超過、onset 08:33:27.96・S窓開始の3秒前・直線性0.79）
  P窓 SNR=0.99 直線性=0.57 → 微妙 / S窓 SNR=1.08 直線性=0.62 → 微妙
```

device2のピークは[図](img/2026-08-26-ibaraki-nanbu-m3.4-8min.png)を見ても記録全体(810秒)で
最も高く孤立しており、タイミングもS窓の直前と近い。ただし**device1は同時刻に対応する
山を作っていない**——他のprobable判定例（[2026-08-08茨城県北部M3.8](2026-08-08-ibaraki-m3.8-post-hoc-detection.md)等）
で見られた「2台が同時刻・同特徴で一致」というパターンが無い。

### 低帯域(0.5-2Hz)・水平2軸

```
device=1  STA/LTA peak=4.97（閾値超過だが onset 08:31:33、P窓の107秒も前）
device=2  STA/LTA peak=4.10（onset 08:33:47.7、S窓終了の7秒後、直線性0.60）
```

低帯域では**標準設定の裏付けにならなかった**——device1の最大ピークは地震発生よりだいぶ前
（無関係な背景ノイズと判断）、device2のピークも標準設定とは別の時刻・低い直線性で、
[図](img/2026-08-26-ibaraki-nanbu-m3.4-lowband-xy.png)を見ても到達窓付近だけが際立って
いるわけではない（記録全体で同程度の山が繰り返し出ている）。

## 判定

**微妙／要検討。** 標準設定でdevice2単独が閾値を超え、タイミングもS波到達に近く孤立した
ピークではあるが、device1の追随が無く、低帯域でも再現しないため2台一致という強い根拠には
届かない。M3.4・震源距離143kmは`docs/detection_range.md`のレンジ内（128〜256km）だが、
今回は判定を上げる材料が揃わなかった。
