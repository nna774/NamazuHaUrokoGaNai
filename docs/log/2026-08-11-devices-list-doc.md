# デバイス一覧をSTATUS.mdに追記した

## 背景

テスト機（device_id=4294967295）のイベントに人工地震フラグを立てる作業の途中で、
このデバイスがどういう素性の機体か（センサ無し・newBatchプール検証用）が
どこにもまとまって書かれていないことに気付いた。`tools/devices.json`は単一の真実
だがHMAC鍵を含むためgitignore対象で、実際の素性は`docs/log/`の個別ログに
断片的に書かれているだけだった。

## 何を決めたか

新規ファイルは作らず、`docs/STATUS.md`の「ハードウェア」節の直前に「デバイス一覧」
節を追加した（[docs/STATUS.md](../STATUS.md#デバイス一覧)）。1号機・2号機・テスト機の
3台をdevice_id・ラベル・センサ・位置づけの表でまとめ、鍵などの機微情報は含めず
`tools/devices.json`と`design.md`へのリンクに留めた。

## なぜそう決めたか

- 既にSTATUS.mdが実機の実装状況をまとめる場所として使われており、新規ファイルを
  増やすと「どこを見ればいいか」がまた増える。ユーザーに確認のうえSTATUS.mdへの
  追記を選んだ。
- テスト機だけでなく1号機・2号機も含めて書くことで、一覧として初見の人が
  device_idから機体を引ける状態にした（テスト機だけ書くと孤立した注記になる）。

## 次に可能になったこと

device_idから機体の素性（実運用機か検証用か、センサの有無）をSTATUS.md一箇所で
引けるようになった。今後デバイスを追加/廃止したらこの表も更新すること。
