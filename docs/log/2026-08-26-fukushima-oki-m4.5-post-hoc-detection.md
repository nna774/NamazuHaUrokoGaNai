# 2026-08-26 福島県沖M4.5 事後解析

`tools/scan_quakes.py`（[2026-08-28の実装](2026-08-28-scan-quakes-jma-feed.md)）が
気象庁の地震一覧から「投げる価値あり」として拾った候補。ユーザーの指示で確認した。
同日08:33の[茨城県南部M3.4](2026-08-26-ibaraki-nanbu-m3.4-post-hoc-detection.md)より
3時間ほど前に発生した別地震。

## 震源要素

気象庁`list.json`より: 発生 2026-08-26 05:23頃(秒不明) JST、震源 N37.4/E141.8、
深さ30km、M4.5、最大震度2、震央距離269km・震源距離271km。

## 1. 自動検知の有無

`/events?all=1&size=20`を確認したが該当時刻付近に`event_id`は無い。

## 2. detectlab解析

### 標準設定（3軸・1-10Hz）

```
device=1  STA/LTA peak=2.37（閾値に遠く未達）
  P窓 SNR=1.00 直線性=0.58 → 微妙 / S窓 SNR=1.04 直線性=0.49 → 微妙
device=2  STA/LTA peak=2.84（閾値未達）
  P窓 SNR=0.97 直線性=0.51 → 微妙 / S窓 SNR=0.94 直線性=0.59 → 微妙
```

両機とも閾値に届かず、P窓・S窓のSNRもほぼ1（[図](img/2026-08-26-fukushima-oki-m4.5-8min.png)）。

### 低帯域(0.5-2Hz)・水平2軸

```
device=1  STA/LTA peak=3.90（僅差で閾値未達）
device=2  STA/LTA peak=6.20（閾値を明確に超過、onset 05:24:38.5・S窓終了の21秒後・直線性0.93）
```

device2のピークは[図](img/2026-08-26-fukushima-oki-m4.5-lowband-xy.png)でも記録全体で
最も高く孤立しており、S窓のすぐ後（コーダ域）というタイミングも実体波の減衰として不自然ではない。
ただし**device1は同時刻に対応する山を作っておらず**（僅差で閾値未達なだけで、他のprobable判定例
で見られる「2台同時に立つ」形にはなっていない）、直線性の一致度パネルもこの時刻だけが
突出しているようには見えない。

## 判定

**微妙／要検討。** 低帯域でdevice2単独が閾値を明確に超過し、タイミング・直線性とも
地震らしい特徴を示すが、device1の追随が無いため2台一致という強い根拠には届かない。
[茨城県南部M3.4](2026-08-26-ibaraki-nanbu-m3.4-post-hoc-detection.md)と同じ「device2だけ
単発で立つ」パターンが同日に2件続いた形——device2の方が背景ノイズが低い
（[docs/noise.md](../noise.md)の通りdevice1よりASDが低い）ぶん、閾値ぎりぎりの揺れを
拾いやすい傾向がある可能性はあるが、2件だけでは断定できない。
