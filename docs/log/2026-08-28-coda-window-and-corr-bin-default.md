# 2026-08-28 detectlab.pyに「コーダ想定域」窓を追加し、`--corr-bin`を常時実行にする

[2026-08-26福島県沖M4.5/茨城県南部M3.4の事後解析](2026-08-26-fukushima-oki-m4.5-post-hoc-detection.md)
での「S波のwindowの後に跳ねてる気がする」という指摘を受けて、`docs/post_hoc_detection.md`に
理論的背景（P窓・S窓は到達"瞬間"の推定幅で揺れの続く長さではない）を書いた。その流れで
「じゃあ検知コード・グラフの窓幅も直すべきか」「`--corr-bin`は常時実行でも問題ないか」と
聞かれ、`detectlab.py`本体を2点改修した。

## 決めたこと

- **リアルタイム検知(detect Lambda・ファーム)は変更不要。** あちらはP窓・S窓を一切使わず、
  震源要素を知らないまま連続STA/LTAで閾値を跨いだら発火するだけの標準的な地震観測網の
  やり方で、窓の解釈問題とは無関係。窓は`detectlab.py`の事後解析・可視化専用の概念。
- **`detectlab.py`のプロットに「コーダ想定域」窓（S窓終了から180秒ぶん）を追加する。**
  P窓・S窓だけでは「窓の中で光らなかった＝地震ではない」と早合点しやすい
  （実際、今回の福島県沖M4.5をP窓・S窓のSNR/直線性だけで「微妙」と最初に判定した）。
  180秒は[岩手県沖M4.9(確定M5.6)の前例](2026-08-09-iwateoki-m4.9-post-hoc-detection.md)の
  減衰時間（160〜180秒）に合わせた。
- **`--corr-bin`をオプトインから常時出力に変える。** 2機重ね描き時、直線性の一致度パネル
  （3段目）は元々`--corr-bin`の有無に関わらず常に計算されていた——`--corr-bin`はその
  既に計算済みの配列をbinごとにテキスト集計するだけなので、追加コストはbinning処理のみ
  （S3取得・重い計算は増えない）。「コストがCPUだけなら常時出しっぱなしでいいのでは」と
  いうユーザーの指摘を受け、オプション自体を「無効化もできる」形にはせず単純に既定を
  「常に20秒binで出す」に変えた（bin幅の変更用に`--corr-bin <秒>`は残す）。

## 実装

`tools/detectlab.py`:
- `CODA_S = 180.0`定数を追加。`--eew`指定時、`arrivals`リストに`("コーダ想定域", ...)`を
  P窓・S窓に続けて追加（S窓終了時刻を起点に180秒ぶん）。既存の`report()`のP窓/S窓と同じ
  ループでSNR/直線性の判定テキストも自動で出るようになった。
- `--corr-bin`のargparse defaultを`None`(未指定なら集計しない)から`20.0`(常に集計する)へ。
  2箇所の呼び出し元（`--event`複数指定・`--at`複数device指定）で
  `if args.corr_bin and len(per_device) == 2:` の条件から`args.corr_bin`のガードを外し、
  `len(per_device) == 2`だけで判定。
- 相関配列の二重計算を避けるリファクタ: `plot_overlay()`に`precomputed_corr`引数を追加し、
  呼び出し元で一度計算した`(t_c, corr)`をテキストレポートとプロットの両方に使い回す。

`tools/tests/test_detectlab.py`にテスト2件追加（コーダ想定域窓の開始位置・長さ、`CODA_S`が
正の値であること）。`pytest tools/tests`は81件通過。

## 動作確認

2026-08-26福島県沖M4.5を`--out`付きで再実行したところ、**新設のコーダ想定域窓
（05:24:17-05:27:17）で両機とも自動的に「地震らしい」判定**（device1: SNR=1.54・直線性=0.62、
device2: SNR=2.09・直線性=0.66）が出た。これは`--corr-bin`の相関binより直接的で強い根拠——
2機が同じ窓で同じ「地震らしい」判定に一致しており、判定基準（[docs/post_hoc_detection.md](../post_hoc_detection.md)
の「probable detection: 2機が同タイミング・同特徴で一致」）に照らすと「弱いprobable」から
更に格上げできる可能性がある。この件はユーザーに報告し、判定・`detection_events.csv`の
tier変更（回帰係数が動く）をやるかは別途確認する。
