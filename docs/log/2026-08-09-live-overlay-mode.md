# ダッシュボードのライブ「1分」表示に複数機の重ね表示モードを追加

## 何を決めたか

`tools/calibrate_orientation.py --write`（#52）で1号機・2号機の傾き・相対方位が
`namazu-devices` に較正済みになったのを受け、ダッシュボードのライブ画面「1分」表示限定で、
較正済みの機を2台以上選ぶと重ね描きするモードを実装した。

実装前に2点をユーザーに確認した:

- **重ねる中身**: UD（鉛直）＋回転済み水平2軸（h1/h2）の3チャンネル・符号付き案を選んだ。
  `docs/device_overlay.md` の a（方位不変・UD+H合成、符号を失う）は見送り、b（方位較正を
  使った回転）を採用。ただし較正で分かるのは基準機からの**相対**方位だけで絶対方位（真北）
  ではない点はUI上の説明文にも明記した。
- **UI配置**: 独立ページではなく既存のライブ画面にトグル（チェックボックス）を追加する形。
- 追加で「`overlay=1,2`のような形でURLに持たせられるか」と聞かれ、単一トグルではなく
  チェック済みdevice_idの配列を`&overlay=<id>,<id>,...`としてURLに持たせる設計にした
  （2台限定にせず、較正済みの機なら何台でも選べる一般的な作りになった）。

## 実装

- **api**: `_device_view`（`lambda/api/handler.py`）に `tilt_up`/`tilt_deg`/`azimuth_deg`/
  `calibration_ref_device` を追加。未較正はnull。`/devices`・`/devices/<id>`両方に乗る。
- **ダッシュボード**: 回転・共通グリッドへのリサンプル・描画はすべてクライアント側
  （`dashboard/app.js`）。概算震度（2026-08-07実装）と同じ設計で、追加のAPI呼び出しは無い。
  - `frameFromUp`/`rotateToChannels`は`tools/calibrate_orientation.py`の
    `frame_from_up`/`DeviceCal`の回転手順をJSへ移植したもの。
  - 較正済みの機だけをチェックボックスにする・「1分」以外では無効化する・
    `calibration_ref_device`が食い違う組み合わせや較正値の無い機を含む組み合わせは
    エラー表示にする、を実装。
  - 通常表示⇄重ね表示でUIの出し分け（デバイス選択・軸チェック・説明文）を切り替える。
  - 計測震度バッジは重ね表示中は機ごとに出す（回転・符号反転に不変なので較正なしでも
    生のx/y/zからそのまま計算できる）。

## 何が覆ったか（実装中に見つけた符号の誤り）

`fit_relative_azimuth`のdocstring「otherを何度回すとrefに一致するか」を素直に読んで
最初は`Rot(+azimuth_deg)`を掛けたが、`tools/calibrate_orientation.py`を実際にPythonで
実行して合成データ（角度25度のタップ）で検算したところ**符号が逆**だった。実際は
`v_ref ≈ Rot(-azimuth_deg)・v_other`。`-azimuth_deg`分だけ回すよう修正し、修正後は
残差が浮動小数点誤差レベル（1e-16）まで一致することを確認した。docstringの文言だけで
実装せず、必ず数値で検算しろという教訓（このリポジトリでは既に何度か踏んでいる話だが）。

`frameFromUp`（JS）も`frame_from_up`（Python）と同じ入力で出力を突き合わせ、
浮動小数点誤差の範囲で一致することを確認済み。

## 確認したこと

- `pytest lambda/tests tools/tests` 169件通過（api の新規テスト2件を追加）。
- `node --check dashboard/app.js`。
- ヘッドレスChromeで実データ（本番API、読み取り専用）に対して通常のライブ表示が
  壊れていないことを確認。
- 重ね表示の本体は、較正値と2台ぶんの合成波形（同じ「真の揺れ」を2つの異なる傾き・
  方位から観測した想定でPython側で生成）をモックAPIで返し、実際の`app.js`のコード
  （フェッチ→回転→共通グリッド補間→描画のフルパイプライン）をヘッドレスChromeで
  実行して確認した。UD/h1/h2が機ごとの色でほぼ完全に重なって描画されること、
  「1分」以外でチェックボックスが無効化されること、較正基準が食い違う/較正値が無い
  組み合わせでエラー表示になることを確認した。
- 本番デプロイ（terraform apply・S3 sync・CloudFront invalidation）はまだ。実機
  device1/device2の実データでの最終確認はデプロイ後。
