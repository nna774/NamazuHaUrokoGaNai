# ジオフォン導入作戦（検討中・未着手）

device1のブロック固定前後比較（[noise.md](noise.md#2026-08-11-device1-単独の固定前後比較同一機体同一センサ)）で、
z軸<0.2Hzのドリフトが据え付けでは削りきれず、残っているのはセンサチップ自体の温度係数(TCO)の
可能性が高いと分かった。ここからMEMS加速度計とは別原理のセンサ——ジオフォン（動電型速度センサ）
——を導入する余地がないか検討した記録。**まだ何も買っていない・作っていない。**

## 1. 動機と期待値（何を解決し、何を解決しないか）

**重要: これは<0.2Hzのドリフト問題そのものへの回答ではない。**

- ジオフォンは磁石+コイルの電磁誘導で速度に比例した電圧を出す受動素子。原理上、
  静的な変位・傾き・温度変化（＝DC付近）を拾わない。**MEMSのTCO・架台の熱ドリフトという
  弱点をそもそも持たない。**
- ただし安価なジオフォン（後述）は固有周波数4.5Hz前後を持ち、それより低い帯域では
  出力が急峻に減衰する（2次系、-12dB/oct）。周期延長回路である程度は下側に伸ばせるが、
  4.5Hz→0.2Hzは4オクターブ半の延長を要求する話で、実用範囲を大きく超える
  （プリアンプの熱雑音ごと増幅してSN比が破綻する）。**<0.2Hzは加速度計でもジオフォンでも
  安価には狙えない**（[noise.md 実務結論](noise.md#実務結論)の「長周期は原理的に不利」は
  ジオフォンでも変わらない）。
- 期待できるのは、**今すでにうまく検知できている1-10Hz帯（P/S実体波）**を、
  **温度ドリフトから解放された別原理のセンサで独立にクロスチェックする**こと。
  MEMSの自己ノイズがジオフォン自己ノイズより高ければ、この帯域のノイズフロアが
  下がる可能性もある（未検証、要実測）。

## 2. 前提: 既存の「センサ差し替え」の枠には乗らない

[design.md §ハードウェアの差し替え可能性](design.md#ハードウェアの差し替え可能性)は
「軽い」差し替えとして`AccelSensor`インターフェース（`begin`/`read`/`scaleMgPerLsb`/
`sensorType`/`sampleFormat`）を前提にしている。これはSPI/I2Cのデジタル出力加速度計
（IIS3DHHC・ADXL355等）を差し替える話で、**ジオフォンはそもそも加速度計ではない**
（アナログ電圧出力・物理量は速度）。この既存の枠には乗らない、新規の統合が要る:

- アナログのプリアンプ回路（出力電圧が微小、低ノイズ増幅が要る）
- 新規のADCパス（既存のSPI経由デジタル読み出しとは別系統）
- 速度という物理量をどう扱うか（既存パイプラインはgal=加速度前提。震度計算に使うなら
  微分が要るが、微分は高域ノイズを増幅する。無理に既存のJMA計算パイプラインへ
  乗せようとせず、**まずは独立した検知用の補助信号として扱う**方が筋がよさそう）

## 3. センサ候補と価格

| | 4.5Hz品(例: SM-24, GS-11D等) | 低周波品(1-2Hz) |
|---|---|---|
| 実売目安 | 2,000〜5,000円 | 数万〜十数万円 |
| 入手性 | AliExpress/eBayで容易 | 専門業者・在庫限定的 |
| 理由 | 資源探査・土木の業界標準でロット生産 | バネを柔らかく・マスを重くする必要があり大型化 |

**4.5Hz品が現実的な出発点。** 低周波品は「本気で長周期を狙う」段階の話で、
§1の通り今回のスコープではない。

## 4. 統合方針（案）: 本線には繋がない、独立した実験機として作る

理由:

- プリアンプのノイズ設計・ADC選定など未検証の要素が多く、いきなりdevice1/2と同じ
  ingestパイプラインに繋いでも「壊れたセンサなのか設置なのか回路なのか」切り分けが
  難しくなる。
- コスト最小化。3軸そろえる（センサ×3+プリアンプ+ADC）前に、**Z軸1本で
  「そもそも自己ノイズが今のMEMSより良いのか」を確かめるのが先**
  （[Gemini相談ログ](https://share.gemini.google/Ykju8c1BUgrr)でも同じ結論）。
- S3/DynamoDBへ送る本番経路に繋ぐかどうかは、実測で価値が確認できてから決める話で、
  最初から決め打ちしない。

### フェーズ案

| phase | やること | ゴール |
|---|---|---|
| 0 | Z軸ジオフォン1個+簡易プリアンプ+適当なADC(ESP32でもマイコン単体でも可)でとりあえずログを取る | 動作確認。既存device1/2とは完全に独立、S3に送る必要すら無い(ローカルCSVで十分) |

| 2 | 既知規模の小さいイベント再来時、または人工加振で、MEMSと同時刻収録してSNR比較 | 「本当にクリーンに実体波が見えるか」を実データで確認 |
| 3(条件付き) | phase2で価値が実証された場合のみ、3軸化・新device_idでの本線統合を検討 | ここではまだ決めない |

## 5. 未検証・要検討の技術的不確定要素

- **プリアンプのノイズ設計**: ゲイン・帯域・電源ノイズ次第では、素人設計だと
  ジオフォン自体の自己ノイズよりプリアンプのノイズが支配的になりうる。低ノイズオペアンプ
  の選定と回路検証が要る。
- **ADCの選定**: ESP32内蔵ADC(12bit、ノイズ・非線形性が大きく低レベル信号には不向き)か、
  外付けの高分解能ADC(例: ADS1115等のΔΣ型、またはオーディオ用ADC)か。サンプルレートを
  既存の100Hzに揃えるか、ジオフォンの帯域(数Hz〜)に合わせて別レートにするかも未決定。
- **速度→既存パイプラインへの接続方法**: 素直に微分して加速度化すると高域ノイズが
  増幅される。無理にJMA計測震度の計算に乗せず、検知用の独立信号（STA/LTA等）として
  使う方が現実的か、要検討。
- **電源**: センサ本体は受動素子で無給電だが、プリアンプ・ADC・マイコンは要る。

## 6. やらないこと（今回のスコープ外）

- **<0.2Hzの長周期対応**: §1の通り、ジオフォンでも安価には解決しない。
- **3軸フル実装**: phase0はZ軸1本のみ。
- **本線ingest/S3への統合**: phase3まで判断しない。
- **断熱等の環境対策**: [noise.mdの対策候補](noise.md#残るドリフトz軸02hzへの対策候補未着手)
  にある断熱・温度補正は別の作戦であり、ここでは扱わない。
