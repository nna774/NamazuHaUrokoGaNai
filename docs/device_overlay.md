# 複数機の波形を重ねる（姿勢・方位の扱い）

1号機（湯沢・IIS3DHHC）と2号機（ADXL355）を並べて比較しようとして、
**そのままでは重ねられない**ことが分かった。2026-08-03 時点の整理と、取りうる手の比較。

**進捗**: どれも未着手。**着手順は未決**（→ [§着手順](#着手順未決)）。

## 1. 何が起きたか

同一時刻・同一窓（`#live?m=1&s=1785688680`）で2機を見比べたところ、2号機のほうが
グラフの振れ幅が大きく、しかし平均的には静かに見えた。原因は2つあり、どちらも
**比較の仕方の問題**であって機体の性能差ではなかった。

### 1.1 自動レンジ（`r=0`）は表示軸の最大値でスケールが決まる

[dashboard/app.js](../dashboard/app.js) の `drawWaveform` は `fixedRange > 0` でなければ
表示中の**全軸**の min/max から縦軸を決める。`ax=xyz` だと z の振れが縦軸を支配し、
x/y はその中で潰れる。**2機を見比べる時は縦軸を固定しろ**（`r=20` 等）。

### 1.2 軸の向きが機体ごとに違う

2号機は仮置きのため約14度傾いている。傾きだけでなく、**水平面内をどちらに向けているかが
不明**なので、x や y を機体間で直接対応させることに意味がない。

### 1.3 実測（比較の基準として残す）

2026-08-03 01:00 頃、`s=1785688680` 付近の静穏12秒。単位 gal、線形デトレンド後の RMS。

| | 傾き | 補正前 x/y/z | 鉛直合わせ後 h1/h2/UD | 水平合成 H |
|---|---|---|---|---|
| 1号機 IIS3DHHC | 1.2度 | 0.151 / 0.190 / 0.201 | 0.190 / 0.151 / 0.201 | 0.113 |
| 2号機 ADXL355 | 14.1度 | 0.136 / 0.159 / 0.270 | 0.159 / 0.140 / 0.268 | 0.103 |

帯域別（2号機、z軸）: 0.1–1Hz = 0.025 / 1–10Hz = 0.079 / **10–50Hz = 0.243**。
1号機 z は 0.034 / 0.088 / 0.173。

- **2号機の z は広帯域で約35%うるさく、中身はほぼ全部 10–50Hz**。尖度 0.18・1秒RMSも
  0.223–0.393 と一様なので、スパイクではなく常時フロアが高い。
  **据え付けが仮であることが効いている**と見ている（→ [§b](#b-方位を較正する)）。
- **低周波（0.1–1Hz）は逆に2号機のほうが静か**。1号機 z の低周波突出は
  [noise.md](noise.md) の記述と整合する。ADXL355 の 1/f が良い期待とも合う。
- **傾き14度を補正しても数値は数%しか動かない**（cos14° = 0.97）。
  「傾きを消せば重なる」わけではない、というのがこの表の要点。

## 2. 原理的な制約

**重力ベクトルから決まるのは鉛直方向だけ**。3自由度の姿勢のうち2つ（傾き）は静置時の
DC で決まるが、**水平面内の回転1自由度（方位）は決まらない**。そして静穏ノイズはほぼ
等方なので、ノイズの統計から方位を逆算することもできない。

方位を決めるには**方向の分かっている振動**が要る。そこが a / b の分かれ目になる。

## 3. 選択肢

### a. 方位不変量に落とす

重力方向で回して `UD = 鉛直成分`、`H = √(h1² + h2²)` の2チャンネルにする。
方位の自由度が消えるので、機体をまたいで素直に重ねられる。

- **できること**: ノイズフロア比較・センサ評価。今の目的にはこれで足りる。
- **限界**: H が非負になり波形の見た目が変わる（符号を失う）。符号付きで見たいなら
  UD だけを重ねる。
- **実装**: ダッシュボードに「方位不変モード」を用意し、2機を重ね描きする。
  較正値（重力DCから求めた傾き）はデバイスごとに持てばよく、イベント待ちが要らない。

### b. 方位を較正する

- **人工加振**: 2台が並んでいるなら机を一発叩き、その区間の水平粒子軌跡の主軸を
  両機で求めて一致させる回転角が方位差。相対方位だけなら今日でも決まる。
  `artificial` フラグを立てておけばイベント一覧は汚れない。
- **実イベント**: P波初動の水平粒子軌跡はラジアル方向（震央方位）を向く。震央は既知
  （[tools/detectlab.py](../tools/detectlab.py) の `--eew`）なので、各機の「北ズレ」が
  **絶対値で**決まる。
- **できること**: N/E/UD に回して符号付きで重ねられる。多点化した時の本筋はこれ。
- **実装**: 一度決めたら `namazu-devices`（[lambda/common/devices.py](../lambda/common/devices.py)）に
  `azimuth_deg` と傾きを持たせて恒久化する。
- **現時点の判断**: **2号機の据え付けが仮**で、それ自体がノイズ源になっている。
  本据え付け（[adxl355.md](adxl355.md) §7）を通してからやる。仮置きのまま較正しても
  据え付け直しで無効になる。

### c. 震度で比べる（姿勢問題を回避する）

計測震度は3成分合成なので**回転・軸入れ替え・符号反転に不変**
（[design.md](design.md) の「向きは自由」節）。「揺れの大きさ」を比べたいだけなら較正は一切要らない。

- **問題**: **ダッシュボードに震度を見るビューが無い**。イベント一覧の確定震度は見られるが、
  連続震度の時系列を2機並べて見る手段がない。
- **やること**: ダッシュボードに連続震度ビューを足す。2機ぶんを同一軸に重ねられれば、
  姿勢の話を一切せずにフロア差（見込み -0.5階級、[adxl355.md](adxl355.md) §1）を
  そのまま読める。
- **注意**: 連続震度の窓長で見え方が変わる（60秒窓 vs 5秒窓、[noise.md](noise.md)）。
  比較には気象庁準拠の60秒窓を既定にする。

## 着手順（未決）

**決まっているのは b が最後になりそうだということだけ**。2号機の本据え付けが前提なので、
それより前に較正しても無効になる。a と c の順序は未定。

判断材料として:

- **c（震度ビュー）** は姿勢の話を回避して2機を比較できる最短経路であり、受け入れ判定
  （[adxl355.md](adxl355.md) §6）にもそのまま使える。
- **a（方位不変モード）** はイベント待ちが不要で、波形レベルで重ねたくなった時に効く。

## 実装メモ（a / b 共通）

- **生データ（raw）は素のまま残し、回転は表示時に掛ける**。較正値は後から変わりうるので、
  保存済みバイナリに焼き込むと較正のやり直しができなくなる。
- 較正値の置き場は `namazu-devices`。api が波形に添えて返し、ダッシュボードが適用する。
- **重ねる時はサンプルクロックが独立**である点に注意。両機とも公称100Hz だが時計は別なので、
  共通グリッドへのリサンプルが要る。
- 波形の組み立ては device_id で絞る（[intensity_pitfalls.md](intensity_pitfalls.md) の
  混在事故）。重ね描きは「1本に連結」ではなく「2本を別系列として描く」こと。
