# 複数機の波形を重ねる（姿勢・方位の扱い）

1号機（湯沢・IIS3DHHC）と2号機（ADXL355）を並べて比較しようとして、
**そのままでは重ねられない**ことが分かった。2026-08-03 時点の整理と、取りうる手の比較。

**進捗**: どれも未着手。**着手順は未決**（→ [§着手順](#着手順未決)）。

## 1. 何が起きたか

同一時刻・同一窓（`#live?m=1&s=1785688680`）で2機を見比べたところ、2号機のほうが
グラフの振れ幅が大きく、しかし平均的には静かに見えた。原因は2つあり、どちらも
**比較の仕方の問題**であって機体の性能差ではなかった。

### 1.1 自動レンジ（`r=0`）は表示軸の最大値でスケールが決まる

[dashboard/app.js](../dashboard/app.js) の `drawWaveform` は `fixedRange > 0` でなければ
表示中の**全軸**の min/max から縦軸を決める。`ax=xyz` だと z の振れが縦軸を支配し、
x/y はその中で潰れる。**2機を見比べる時は縦軸を固定しろ**（`r=20` 等）。

### 1.2 軸の向きが機体ごとに違う

2号機は仮置きのため約14度傾いている。傾きだけでなく、**水平面内をどちらに向けているかが
不明**なので、x や y を機体間で直接対応させることに意味がない。

### 1.3 実測（比較の基準として残す）

2026-08-03 01:00 頃、`s=1785688680` 付近の静穏30秒（api は `minutes=0.2` で要求しても
バッチ単位で返すので実際は30秒ぶん来る）。単位 gal、線形デトレンド後の RMS。

| | 傾き | 補正前 x/y/z | 鉛直合わせ後 h1/h2/UD | 水平合成 H |
|---|---|---|---|---|
| 1号機 IIS3DHHC | 1.2度 | 0.151 / 0.190 / 0.201 | 0.190 / 0.151 / 0.201 | 0.113 |
| 2号機 ADXL355 | 14.1度 | 0.136 / 0.159 / 0.270 | 0.159 / 0.140 / 0.268 | 0.103 |

帯域別（2号機、z軸）: 0.1–1Hz = 0.025 / 1–10Hz = 0.079 / **10–50Hz = 0.243**。
1号機 z は 0.034 / 0.088 / 0.173。

- **傾き14度を補正しても数値は数%しか動かない**（cos14° = 0.97）。
  「傾きを消せば重なる」わけではない、というのがこの表の要点。
- **低周波（0.1–1Hz）は2号機のほうが静か**。1号機 z の低周波突出は
  [noise.md](noise.md) の記述と整合する。ADXL355 の 1/f が良い期待とも合う。
- この表の**2号機 z = 0.270 はシーリングファンに汚染されている**。
  → [§1.4](#14-この測定は外乱を掴んでいた犯人はシーリングファン)

### 1.4 この測定は外乱を掴んでいた（犯人はシーリングファン）

上表を撮った 01:00 は、**2号機だけに 49.65Hz の鋭い線**が立っていた（z軸で床の 7.7倍、
x軸で 6.7倍。1号機には無い）。**近くのシーリングファンを止めたら消えた**（2026-08-03 実施）。

| z軸 | 01:00 ファン稼働 | ファン停止後 |
|---|---|---|
| 1号機 | RMS 0.201（25–40Hz 0.105 / 49–50Hz 0.028） | 0.196（0.105 / 0.027） |
| 2号機 | RMS 0.270（25–40Hz 0.205 / 49–50Hz 0.078） | **0.199**（0.098 / 0.025） |

- **1号機は前後で不動、2号機だけが動いた**。同じ部屋でも据え付けの結合次第でこれだけ差が出る。
- 外乱を除くと **2号機 z (0.199) と1号機 z (0.196) はほぼ同じ**。水平は 2号機のほうが明確に
  静か（x 0.130 / y 0.130 対 1号機 0.157 / 0.189）。
  **「ADXL355 のほうがうるさい」は誤り**で、据え付けが仮であることのせいでもなかった。
- **商用電源とは無関係**だった。ファンの回転は数Hzなので 49.65Hz は羽根の回転ではなく、
  モータの極数×回転数（コギング/転流リプル）と見るのが素直。系統周波数は 50.00±0.2Hz に
  保たれるので、**50.00 から 0.35Hz も外れている時点で電源同期ではない**。
- サンプルクロック誤差説も否定できる。読みは `esp_timer_start_periodic`（40MHz水晶、
  ±20ppm級）なので、0.7%=7000ppm のずれは出ない。

### 1.5 サンプリング100Hzはこのままでよい（200Hz化は解にならない）

上の件で「100Hz をやめて 200Hz にすべきでは」を検討した。**結論は現状維持**。
根拠は [design.md](design.md) の「サンプリングとオーバーサンプリング」に加えて以下。

**震度には効かない。** JMAフィルタの利得（1Hz基準）は 20Hz で -25dB、30Hz で -39dB、
**50Hz で -64dB**。50Hz付近の線が何であれ計測震度には現れない。実害があるのは
**0–10Hz へ折り返してくる成分**だけで、そこは `sqrt(1/f)` の周期補正で増幅される。

**200Hz にしても折り返し耐性は改善しない。** 1kHz 読みのまま出力を上げると平均点数が
10点→5点に減る。危険帯が 90–110Hz から 190–210Hz へ移るだけで、阻止量はほぼ同じ:

| 折返し元 → 先 | 10点平均（現行・出力100Hz） | 10点2段=三角窓 | 5点平均（出力200Hz） |
|---|---|---|---|
| 95Hz → 5Hz | -25.5 dB | **-51.0 dB** | （帯域内） |
| 105Hz → 5Hz | -26.3 dB | **-52.6 dB** | （帯域内） |
| 190Hz → 10Hz | -25.2 dB | -50.4 dB | -25.1 dB |
| 195Hz → 5Hz | -31.3 dB | -62.6 dB | -31.3 dB |
| 100/200/300Hz → DC | **-∞（ヌル）** | -∞ | -∞（200Hzのみ） |

**むしろ 100Hz は 50Hz 環境に対して偶然よい。** 10点移動平均のヌルが 100Hz の整数倍に
ちょうど入るので、**50Hz の偶数次高調波（100/200/300Hz、変圧器磁歪の主成分 2f=100Hz を
含む）が完全に消える**。200Hz 出力にするとこの性質を失ううえ、**2f=100Hz が新しい
ナイキストにちょうど乗る**（同じ罠の再来）。電源から本気で逃げるなら 200 ではなく
**250Hz（`kOversample=4`）**で、50Hz も 100Hz も帯域内に収まる。

**改善したいなら平均を2段にする（三角窓）。** 1kHz 読みのまま 10点移動平均を2回通してから
間引く。実害である 90–110Hz → 0–10Hz の折り返しが **-25dB → -51dB** になる。通過域の垂下は
10Hz で -0.3dB、20Hz で -1.2dB だが、JMAハイカットが同帯域で既に -13/-25dB なので実質無視できる。
**ただし `tools/backtest.py` での数値照合は必須**。

**200Hz は診断用の一時モードとしてなら価値がある。** ノイズ源の同定はこのプロジェクトの
本丸（[noise.md](noise.md)）なので、折り返しを解いて真の周波数を見る手段は持っておきたい。
恒久化はしない。恒久化のコストは保存量2倍、FIR再設計（[tools/jismo/fir.py](../tools/jismo/fir.py) は
100Hz・511tap 前提）、`firmware/lib/Shindo/Shindo.h` の `kSampleRateHz`/`kWindowSamples`、
ファームのFIR演算量が約4倍。

保存量について念のため: **1kHz の読みは平均に使うだけで保存も送信もしていない**。
S3 に載るのは間引いた後の出力レートぶんだけなので、**出力を 200Hz にすればそのまま2倍**に
なる。int16×3軸で 600 B/s = 52MB/日/台 → 104MB/日/台。ADXL355 は 20bit で int32 なので
更に倍（`main.cpp` のバッチRAMが int16 18KB / int32 36KB と倍違うのも同じ理由。
2号機の `kBatchSeconds` が 15 なのはRAMを揃えるためで、1バッチ 1500 サンプルになる）。

震度への影響はほぼ無いが、**広帯域RMSと STA/LTA のフロアは持ち上げる**ので微弱地震の
検出には邪魔になる。ノイズフロアを測る時は**近くの回転機械を止めてから測れ**。

## 2. 原理的な制約

**重力ベクトルから決まるのは鉛直方向だけ**。3自由度の姿勢のうち2つ（傾き）は静置時の
DC で決まるが、**水平面内の回転1自由度（方位）は決まらない**。そして静穏ノイズはほぼ
等方なので、ノイズの統計から方位を逆算することもできない。

方位を決めるには**方向の分かっている振動**が要る。そこが a / b の分かれ目になる。

## 3. 選択肢

### a. 方位不変量に落とす

重力方向で回して `UD = 鉛直成分`、`H = √(h1² + h2²)` の2チャンネルにする。
方位の自由度が消えるので、機体をまたいで素直に重ねられる。

- **できること**: ノイズフロア比較・センサ評価。今の目的にはこれで足りる。
- **限界**: H が非負になり波形の見た目が変わる（符号を失う）。符号付きで見たいなら
  UD だけを重ねる。
- **実装**: ダッシュボードに「方位不変モード」を用意し、2機を重ね描きする。
  較正値（重力DCから求めた傾き）はデバイスごとに持てばよく、イベント待ちが要らない。

### b. 方位を較正する

- **人工加振**: 2台が並んでいるなら机を一発叩き、その区間の水平粒子軌跡の主軸を
  両機で求めて一致させる回転角が方位差。相対方位だけなら今日でも決まる。
  `artificial` フラグを立てておけばイベント一覧は汚れない。
- **実イベント**: P波初動の水平粒子軌跡はラジアル方向（震央方位）を向く。震央は既知
  （[tools/detectlab.py](../tools/detectlab.py) の `--eew`）なので、各機の「北ズレ」が
  **絶対値で**決まる。
- **できること**: N/E/UD に回して符号付きで重ねられる。多点化した時の本筋はこれ。
- **実装**: 一度決めたら `namazu-devices`（[lambda/common/devices.py](../lambda/common/devices.py)）に
  `azimuth_deg` と傾きを持たせて恒久化する。
- **現時点の判断**: **2号機の据え付けが仮**なので、本据え付け
  （[adxl355.md](adxl355.md) §7）を通してからやる。仮置きのまま較正しても据え付け直しで
  無効になる。方位も傾きも据え付けで変わる量である以上、これは動かせない前提だ。

### c. 震度で比べる（姿勢問題を回避する）

計測震度は3成分合成なので**回転・軸入れ替え・符号反転に不変**
（[design.md](design.md) の「向きは自由」節）。「揺れの大きさ」を比べたいだけなら較正は一切要らない。

- **問題**: **ダッシュボードに震度を見るビューが無い**。イベント一覧の確定震度は見られるが、
  連続震度の時系列を2機並べて見る手段がない。
- **やること**: ダッシュボードに連続震度ビューを足す。2機ぶんを同一軸に重ねられれば、
  姿勢の話を一切せずにフロア差（見込み -0.5階級、[adxl355.md](adxl355.md) §1）を
  そのまま読める。
- **注意**: 連続震度の窓長で見え方が変わる（60秒窓 vs 5秒窓、[noise.md](noise.md)）。
  比較には気象庁準拠の60秒窓を既定にする。

## 着手順（未決）

**決まっているのは b が最後になりそうだということだけ**。2号機の本据え付けが前提なので、
それより前に較正しても無効になる。a と c の順序は未定。

判断材料として:

- **c（震度ビュー）** は姿勢の話を回避して2機を比較できる最短経路であり、受け入れ判定
  （[adxl355.md](adxl355.md) §6）にもそのまま使える。
- **a（方位不変モード）** はイベント待ちが不要で、波形レベルで重ねたくなった時に効く。

## 実装メモ（a / b 共通）

- **生データ（raw）は素のまま残し、回転は表示時に掛ける**。較正値は後から変わりうるので、
  保存済みバイナリに焼き込むと較正のやり直しができなくなる。
- 較正値の置き場は `namazu-devices`。api が波形に添えて返し、ダッシュボードが適用する。
- **重ねる時はサンプルクロックが独立**である点に注意。両機とも公称100Hz だが時計は別なので、
  共通グリッドへのリサンプルが要る。
- 波形の組み立ては device_id で絞る（[intensity_pitfalls.md](intensity_pitfalls.md) の
  混在事故）。重ね描きは「1本に連結」ではなく「2本を別系列として描く」こと。
