# UPS導入作戦（方針決定・発注済み、実機検証中）

2026-08-27朝5時頃の停電でdevice2(ADXL355機)が電源断で停止した。device3(ピエゾ)は
まだ意味あるデータが取れていない実験機なので後回しでよいが、device2は継続稼働させたい、
という動機から検討した記録。

**化学種はLiFePO4に決めた**（経緯は[log/2026-09-02-ups-lifepo4-direction-and-order.md](log/2026-09-02-ups-lifepo4-direction-and-order.md)）。
当初はAdafruit PowerBoost 1000C(Li-ion/LiPo用)+保護回路内蔵LiPoセルで検討していたが、
「セルを自分で買うのが怖い」という理由でLi-ion/LiPo系(熱暴走しやすい)からLiFePO4
(熱的に安定)へ切り替えた。完成品UPS対応モバイルバッテリーやAmazon.co.jpの汎用Li-ion
UPSモジュールも代替案として検討したが、いずれも却下——却下理由は上記ログ参照。

## 1. 前提: Electabuzzの構成とは切り分ける

[Electabuzz](https://github.com/nna774/Electabuzz)側でも複数デバイス前提のUPS化を
検討中だが、そちらは台数分のコストが嵩む相談になっている。Namazuは今のところdevice2
1台の話なので、同じ土俵で考える必要はない。

## 2. 発注した構成

- **充放電UPSモジュール**: Eletechsup系「LFUPSMA」互換品（AliExpress、モデル番号
  LFUPSMA、Output 5V品、795円）。入力DC5V(>1A)・出力DC5V/1A、32140/32700/18650/
  3.6Vセル対応、`IN+/IN-`・`B-/B+`とも基板パッド直付け(JST-PH等のコネクタ制約なし)。
  基板シルクの注記: 「電池を繋がないと出力電圧が一切出ない」「負荷接続前にフル充電
  しておくこと」「充放電電流が定格の50%を超えると発熱、放熱要」
  - 基板上に`CR`(充電中)・`OK`(満充電)と見られる2つのステータスLEDあり。両方消灯なら
    USB給電断(=バッテリー駆動中)の推定に使える可能性がある。ただし無銘ICでデータ
    シートが無く、電圧レール・オープンドレインかどうかは実機到着後の実測待ち（§4）
  - 1S(単セル)設計。複数セルの直列/並列運用は想定されていない
- **バッテリー**: オーム電機 LS-BLFP18A-S(18650形、3.2V、1800mAh、2本入)。ヨドバシ・
  カインズ・ヤマダ電機等の国内量販店でも扱いのある正規品。PSEマーク取得・JBRC回収
  対象を確認済み（lang-ship.comのブログ記事で実機写真ベースの裏取り済み）。同記事に
  「専用充電器以外(=通常のLi-ion用4.2V系充電器)で充電すると過充電になる」との警告
  あり——LFUPSMA(LiFePO4用3.6V終止)との組み合わせが必要な理由と符合する
  - 2本セットだが**並列接続はしない**。並列は直列バランスとは別種のリスク(電圧不一致
    による突入電流、片方の内部短絡がもう片方から"焚き付けられる"故障波及、LFUPSMAが
    合成電圧しか見えず個別セル監視ができない)を持ち込む上、LFUPSMA自体が1S設計。
    1本を運用に使い、もう1本は交換用の予備として温存する
    (LiFePO4は自己放電が小さく保管に強い)
- **入力ケーブル**: USB Male 2pin裸線ピグテール(AliExpress)。モバイルバッテリーではなく
  普通のAC-USB壁アダプタから`IN+/IN-`へ給電する——壁アダプタなら電池管理機能由来の
  低電流自動シャットオフの心配が無い
- **配線材**: 22AWGより線。短距離・1A級で電流容量・電圧降下とも余裕あり

保護回路(過充電・過放電・過電流カット)は**LFUPSMA側の充放電IC**が担う設計（商品説明に
明記）。LS-BLFP18A-S自体が個別に保護回路を内蔵しているかは不明だが、PSE認証は異常時
(過充電・過放電・短絡等)にセル自体が破裂・発火せず安全に壊れることの担保になるため、
LFUPSMA側の制御が多少不完全でもセル側が緩衝材として働く——ただし慢性的な軽度の過充電
はセル劣化を早める方向に効くため、§4の実測は省略しない。

## 3. 電池選定の根拠

- device2の実消費電流(平均・ピーク、WiFi送信時込み)は**まだ実測していない**。1800mAh
  という容量は「桁感として数百mA級の消費なら数時間は稼げるはず」という見立てに基づく
  もので、根拠として薄いままなのは変わっていない（§5）

## 4. 電源状態の取得可否

LFUPSMAの`CR`/`OK`ステータスLEDノードを分圧して読む案（§2参照）が有力。
2026-09-10の初回通電試験（[log/2026-09-10-ups-first-power-on-test.md](log/2026-09-10-ups-first-power-on-test.md)）で以下を確認した:

- **USB給電が切れると充放電IC自体が電源を失い、CRを含め両LEDが消灯すると確認した**。
  「両方消灯=バッテリー駆動中」の3値信号として使える見込みが立った
- 実測した状態遷移: バッテリーあり・USBあり(充電中)→CR点灯／バッテリーあり・USBなし→
  両方消灯／バッテリーなし・USBあり→OK点灯を一度見たが再現せず(過渡現象の疑い、
  実運用ではバッテリー常時接続前提のため深追いしていない)
- 無瞬断切替も同時に確認した: 出力5V系に仮設置したLEDが、USB(AC側)の抜き差しで
  点灯状態・明るさとも変化しなかった
- **CR/OKはどちらも固定表示ではなく動的に再評価されると確認した**
  （[log/2026-09-15-ups-charge-completion-ok-observed.md](log/2026-09-15-ups-charge-completion-ok-observed.md)）。
  電源再投入(2026-09-11)に加え、OK点灯中に負荷を一瞬繋いで電圧を沈ませただけでも
  即座にCRへ戻ることを確認した

以下は未確定のまま持ち越し:

- `CR`/`OK`のプルアップ先電圧レール（5V系かそれ以下か）
- オープンドレイン(LED経由でGNDへ沈める方式)かどうか
- 分圧が必要な場合、ESP32のGPIO/ADC耐圧3.3Vを超えない値まで落とす必要がある

## 5. 未解決事項

- device2の実消費電流を実測していない（§3、未解消のまま持ち越し）
- LFUPSMAの充放電挙動を2026-09-10〜11に検証した（[log/2026-09-10-ups-first-power-on-test.md](log/2026-09-10-ups-first-power-on-test.md)）。
  バッテリー到着時3.34Vからの充電電圧推移をログしたところ21:45(3.59V)〜01:47(翌日、3.59V)の
  4時間ほぼ横ばい・CR点灯継続で頭打ちに達したと見えたが、CR→OKへの切り替わりはこの
  セッションでは確認できなかった。放電試験後の別サイクル(2026-09-14〜15)で完了に
  至ったことを踏まえると、**この時のセッションは無瞬断切替の確認等でUSBを何度も
  抜き差ししており、完了判定(タイマーや電流積算に依存する可能性がある)が一度も
  完了に到達していなかった「まだ充電中の踊り場」だった可能性が高い**——3.59Vという
  値自体を実際の終止電圧とみなすのは適切でない
- **CR→OKへの切り替わり(充電完了)を2026-09-15に初めて観測した**
  （[log/2026-09-15-ups-charge-completion-ok-observed.md](log/2026-09-15-ups-charge-completion-ok-observed.md)）。
  放電試験後に空近く(無負荷2.35〜2.36V)から中断無しで充電させたところ、19:03時点の
  3.37Vからほぼ横ばいのまま翌12:28にOK点灯・充電停止(3.38V)を確認した。ただし
  切り替わった正確な瞬間は就寝中で見ていない——12:28の3.38Vは切り替わり後に
  無負荷でしばらく休んだ結果のリラクゼーション後の値である可能性が高く、切り替わり
  瞬間の真の電圧は不明のまま。次に機会があれば、切り替わりの瞬間に立ち会うことを
  優先したい
- 放電側(2.5V付近で止まるか)は2026-09-14に検証した（次項）
- LFUPSMAの放電側挙動を2026-09-14に検証した（[log/2026-09-14-ups-discharge-test.md](log/2026-09-14-ups-discharge-test.md)）。
  220Ω×8並列+330Ω/LED(出力側約190mA)で放電させたところ、**想定していた「2.5V付近で
  モジュール側保護が効いて止まる」は外れた**——実際に起きたのは出力電圧が1.8Vまで
  低下する現象で、バッテリー電圧(2.22V付近)からダイオード1個分の電圧降下を引いた
  値とほぼ一致することから、ブースト昇圧ICがUVLOでスイッチングを止め内部ダイオードを
  素通ししているだけと考えられる。**これが意図した保護(電池を負荷から遮断)なのか、
  電池が依然として負荷に直結したままなのかは判別できていない**。念のため手動で
  負荷を切り離した。負荷撤去直後、B+/B-は2.21V→2.36Vまで急回復しており、放電中の
  低電圧読みのかなりの部分は約190mA負荷時の電圧サグだったとわかった
- **充電直後の電圧(3.59V)は真の満充電OCVより高く出ていた可能性がある**。3日間
  バッテリー単体で無負荷放置したところ3.5V程度まで下がっており、これは自己放電
  だけでは説明しづらい下がり幅——充電直後特有のリラクゼーション(表面電荷)の影響と
  考えられる。以後、満充電・空の判定は直後の読みではなく数時間〜半日休ませてから
  行う方が真のSOCに近い
- 電池+LFUPSMAをdevice2の筐体内にどう収めるかは未検討
  （据え付け先の物理配置は[adxl355.md](adxl355.md)参照）
- firmware側の変更要否・電源状態(§4)をテレメトリとして送るかどうかは決めていない
